# React Code Exports 가이드

> Draft · Version 0.1 · 2026-08-05

## 1. 목적

Figma 디자인을 프로젝트 기준에 맞는 React와 Tailwind CSS 코드로 변환하기 위한 최소 원칙을 정리합니다. 자동 생성 결과는 구현 초안으로 사용하며, 최종 구조와 품질은 프론트엔드 개발자가 검수합니다.

이 문서는 디자이너, 프론트엔드 개발자와 AI 코드 작업자를 대상으로 하며, 프론트엔드 개발자가 운영합니다.

## 2. 적용 기술

- Next.js App Router
- React와 TypeScript
- Tailwind CSS
- shadcn/ui
- Figma Dev Mode
- Tokens Studio

정확한 버전은 프로젝트의 Lock File과 Front-End 초기 구축 가이드를 기준으로 합니다.

## 3. 역할과 책임

### 디자이너

- 가능한 경우 공통 컴포넌트 인스턴스를 사용하고 임의로 분리하지 않습니다.
- 주요 화면 구조는 Auto Layout을 우선 사용합니다.
- 제공된 Variables와 Styles를 사용합니다.
- 코드 구조를 고려해 모든 레이어 이름을 정리할 책임은 지지 않습니다.

### AI 코드 작업자

- Figma 구조만으로 판단하지 않고 프로젝트의 기존 컴포넌트와 토큰을 함께 확인합니다.
- 생성 결과를 완성 코드가 아닌 검토가 필요한 초안으로 제공합니다.
- 불명확한 동작이나 데이터 의미를 임의로 확정하지 않습니다.

### 프론트엔드 개발자

- 변환 범위와 기존 컴포넌트의 재사용 기준을 정합니다.
- 생성 결과의 구조, 접근성, 반응형 동작과 중복을 검수합니다.
- 예외를 승인하고 이 문서를 유지합니다.

## 4. 기본 변환 흐름

1. 구현할 Figma 화면 또는 영역을 지정합니다.
2. Figma의 컴포넌트, Auto Layout, Variables와 화면 의도를 확인합니다.
3. 기존 shadcn/ui 및 프로젝트 컴포넌트와 디자인 토큰을 우선 적용합니다.
4. 기존 요소로 표현할 수 없는 부분만 새 컴포넌트로 작성합니다.
5. 생성된 화면을 Figma와 비교하고 프로젝트 품질 기준으로 검수합니다.

Code Connect 없이도 위 흐름이 동작하도록 운영합니다.

> **TBD:** Code Connect는 Figma Organization 또는 Enterprise 플랜 비용, 좌석과 권한, 저장소 연결 정책을 검토한 후 도입 여부를 결정합니다.

## 5. Figma 해석 기준

의미 있는 레이어 이름은 코드 생성 정확도를 높이는 권장사항이며 필수 조건은 아닙니다. 기본 이름이 남아 있더라도 화면의 시각적 구조, 텍스트, 컴포넌트 정보와 프로젝트 소스를 함께 분석해 구현합니다.

레이어 이름만으로 판단하기 어려운 동작, 데이터 의미와 반응형 규칙은 프론트엔드 개발자가 설명을 추가하거나 담당자에게 확인합니다. 색상, 간격과 크기는 레이어 이름보다 Variables와 Auto Layout을 우선 기준으로 사용합니다.

## 6. 토큰과 컴포넌트 사용

- Tokens Studio와 Figma Variables의 값을 프로젝트의 Tailwind 토큰에 연결합니다.
- 화면별 임의 색상과 간격 값을 반복하지 않습니다.
- shadcn/ui는 수정 가능한 UI 원형으로 사용합니다.
- 업무 의미를 포함한 컴포넌트는 해당 기능 가까이에 둡니다.
- 기존 컴포넌트가 있으면 동일한 요소를 새로 생성하지 않습니다.
- 디자인과 코드의 값이 다르면 한쪽을 임의로 정답으로 간주하지 않고 차이를 확인합니다.

## 7. 컴포넌트와 파일 분리

파일은 Figma의 Frame이나 Group 수, JSX 길이 또는 Tailwind 클래스 수가 아니라 역할, 상태 소유권, 재사용 범위와 변경 이유를 기준으로 나눕니다.

- 단순한 화면은 적은 파일로 시작합니다.
- 특정 기능에서만 사용하는 UI는 해당 feature 가까이에 둡니다.
- 하나의 애플리케이션에서 반복되는 UI는 앱 공통 영역을 검토합니다.
- 여러 애플리케이션에서 의미와 변경 이유가 같은 UI만 공통 패키지로 이동합니다.
- 독립적인 동작, 상태, 주요 조건 분기 또는 실제 재사용이 확인될 때 컴포넌트를 분리합니다.
- 필요가 확인되지 않은 wrapper, hook, store, variant 또는 별도 타입 파일을 미리 만들지 않습니다.

## 8. 완료 기준

- 기존 컴포넌트와 디자인 토큰을 우선 사용했는가?
- 화면의 주요 구조와 상태가 Figma 의도와 일치하는가?
- 의미 있는 HTML과 키보드·포커스 기본 동작을 유지하는가?
- 모바일 및 필요한 반응형 범위를 확인했는가?
- 불필요한 공통화와 파일 분리가 없는가?
- TypeScript 검사, lint와 production build를 통과하는가?

AI 또는 Figma에서 생성한 코드는 사람이 작성한 코드와 같은 리뷰와 검증 기준을 적용합니다.
