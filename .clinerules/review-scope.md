# 프론트엔드 가이드 리뷰 규칙

이 규칙은 사용자가 코드나 가이드를 리뷰하거나 누락 사항을 찾아 달라고 요청할 때만 적용한다. 사용자가 명시적으로 구현을 요청하지 않은 리뷰는 항상 읽기 전용이다.

## 범위

- 사용자가 지정한 파일과 폴더만 검토한다.
- 모든 지적은 지정 범위 안의 실제 코드에 근거해야 한다.
- 각 지적에 정확한 파일 경로를 제시한다.
- 근거가 없으면 추측하지 않는다.
- 누락 사항이 없으면 없다고 답하고 종료한다.

## 단일 파일 및 간단한 파일 리뷰

사용자가 한 개 이상의 파일을 직접 지정하거나 첨부하여 리뷰를 요청하면 다음 규칙을 최우선으로 적용한다.

- 지정되거나 첨부된 파일만 읽고 리뷰한다.
- 프로젝트 구조를 파악하려고 하지 않는다.
- 다른 파일, 폴더, 의존성 또는 연관 구현을 찾아보지 않는다.
- `search_codebase` 또는 이와 유사한 코드베이스 검색 도구를 사용하지 않는다.
- 지정되지 않은 파일을 `read_files` 또는 이와 유사한 파일 읽기 도구로 열지 않는다.
- 파일을 찾거나 조사하기 위한 터미널 명령을 실행하지 않는다.
- import 대상, 호출 대상 및 타입 정의가 다른 파일에 있더라도 따라가서 읽지 않는다.
- 현재 파일만으로 판단할 수 없는 사항은 추측하지 말고 `현재 파일만으로 판단할 수 없음`이라고 표시한다.
- 추가 파일이 반드시 필요하면 직접 찾지 말고, 필요한 이유와 파일 하나만 사용자에게 요청한 뒤 멈춘다.
- 사용자가 단순 리뷰를 요청했다면 작업 계획이나 분석 계획을 먼저 작성하지 않고 곧바로 결과를 제시한다.
- 리뷰 결과는 최대 3개 항목으로 제한한다.

사용자가 `전체 프로젝트`, `전체 폴더`, `관련 파일까지`처럼 탐색 범위를 명시적으로 확장한 경우에만 다른 파일을 검색하거나 읽을 수 있다. `전반적으로`, `충분한지`, `부족한 부분` 같은 표현은 범위 확장 허가로 해석하지 않는다.

## 리뷰 중 금지되는 내용

사용자가 명시적으로 요구하지 않는 한 다음 내용을 작성하지 않는다.

- 백엔드, API 서버, 데이터베이스 또는 인증 시스템의 구현과 설계
- 보안 아키텍처, 인프라, 배포 또는 운영 계획
- 새 기능, 아키텍처 개편 또는 범위 밖 개선 제안
- 구현 계획, 작업 단계, 로드맵 또는 체크리스트
- 기간, 공수, 인원, 우선순위 또는 일정 추정
- 지정 범위 밖의 파일과 시스템에 대한 추론

프론트엔드 코드에 API 호출이나 인증 관련 이름이 있어도 백엔드 또는 보안 설계로 검토 범위를 확장하지 않는다.

## 출력 형식

근거가 확인된 항목만 최대 5개 작성한다. 각 항목에는 다음 내용만 포함한다.

1. 중요도
2. 정확한 파일 경로와 코드 근거
3. 누락되었거나 실제 코드와 충돌하는 가이드 내용
4. 가이드에 추가할 간결한 문장

근거가 있는 누락이 없으면 다음 문장만 출력한다.

`요청된 범위에서 코드 근거가 있는 가이드 누락을 찾지 못했습니다.`

리뷰 뒤에 구현 계획이나 후속 작업 제안을 추가하지 않는다.
