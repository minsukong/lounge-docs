# Figma 구현 작업 흐름

> 기준 원본: `lounge-docs/ui_guide/react_code_exports.html`, `lounge-docs/storybook_guide/index.html`
>
> 이 문서는 AI 코딩용 요약입니다. 충돌하거나 세부 판단이 필요하면 기준 원본을 확인합니다.

## 작업 전

1. 구현할 Figma 화면, 영역과 대상 라우트를 확인합니다.
2. `docs/ai/ui.md`, 관련 라우트, 기존 컴포넌트와 `globals.css` 토큰을 읽습니다.
3. Figma의 컴포넌트, Auto Layout, Variables, Styles와 화면 상태를 확인합니다.
4. 기존 코드와 재사용할 항목을 먼저 정리합니다.

## 구현

- 결과는 현재 앱에서 실행되는 React + TypeScript 컴포넌트로 만듭니다.
- 레이아웃과 스타일은 Tailwind CSS 4로 구현합니다.
- 기존 shadcn/ui와 프로젝트 토큰을 우선 매핑합니다.
- Figma 이름을 그대로 파일 구조로 복사하지 않고 기능과 책임에 맞게 배치합니다.
- Figma에 없는 기능, 데이터 흐름 또는 상태를 임의로 만들지 않습니다.
- 불명확한 값은 숨겨서 확정한 것처럼 작성하지 않고 확인이 필요한 항목으로 남깁니다.
- 공통·재사용 컴포넌트가 확실하면 실제 컴포넌트와 Story를 함께 작성하고 Storybook에서 먼저 독립 상태를 확인한 뒤 화면에 사용합니다.
- 재사용 여부가 불확실한 UI는 기능 가까이에서 먼저 구현하고 실제 반복이 확인될 때 공통 컴포넌트와 Story로 분리합니다.

## 완료 확인

- 주요 구조, 간격, 타이포그래피와 상태가 Figma 의도와 맞는지 비교합니다.
- 필요한 화면 너비에서 레이아웃을 확인합니다.
- 접근 가능한 이름, 키보드 동작과 의미 구조를 확인합니다.
- TypeScript 검사, Lint와 관련 Test를 실행합니다.
- Story를 추가하거나 변경했다면 Storybook 정적 Build와 프로젝트에 합의된 Story 검사를 실행합니다.
- 자동 검사로 판단할 수 없는 시각 차이와 미확정 사항을 별도로 알립니다.
