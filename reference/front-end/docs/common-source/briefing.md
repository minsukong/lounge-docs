# 공통 소스 가이드 활용 브리핑

## 종합 평가

이 문서 묶음은 실제 Front-end 저장소가 만들어졌을 때 첫 기능을 안전하게 시작하기 위한 구현 기준으로 사용할 수 있습니다. 완성된 프로젝트 템플릿은 아니지만, 현재처럼 화면 기획과 제품 계약이 많이 확정되지 않은 상황에서 미리 준비할 수 있는 범위는 충분히 담고 있습니다.

가이드의 예시를 한 번에 모두 복사하는 것이 목표는 아닙니다. 실제 저장소의 생성 결과와 기존 코드를 먼저 확인하고, 첫 사용처가 생긴 항목만 비교·병합해 적용하는 것이 이 가이드의 사용 방식입니다.

## 프로젝트 시작에 도움이 되는 부분

| 영역 | 가이드가 제공하는 것 | 실제 적용할 때 확인할 것 |
| --- | --- | --- |
| UI 설정 | 디자인 전에도 사용할 수 있는 의미 기반 토큰과 shadcn 설정 | 브랜드 값, 실제 shadcn 생성 결과와 디자인 기준 |
| React | QueryClient 생명주기와 반복되는 폼 동작 예시 | 서버 상태 사용 여부와 Query 정책, 실제 반복 사용처 |
| TypeScript | 공통 검사 강도와 외부 입력을 확인하는 함수 | 실제 API·Bridge 응답 형식과 기존 compiler 설정 |
| 테스트 | Client Component와 Query 컴포넌트를 검증하는 환경 | 설치 버전, 기존 테스트 도구와 실행 명령 |
| 통합 사용 | 조회·검증·화면 상태·수정·테스트를 연결한 기능 예시 | API 경로, 인증, 응답 형식, 문구와 route |

[Tailwind CSS와 UI 설정](./tailwind.md)은 디자인 값이 바뀌어도 화면 코드의 역할 이름을 유지할 수 있게 합니다. [React 공통 코드](./react.md)와 [TypeScript 공통 설정과 검사 함수](./typescript.md)는 서버 상태와 외부 입력을 기능 코드에 연결하는 기준을 제공합니다. [테스트 공통 설정](./test.md)과 [통합 사용 예시](./recipes.md)는 이 코드가 실제 사용 흐름에서 동작하는지 확인하는 방법을 보여 줍니다.

## 현재 범위가 적절한 이유

- 디자인이 확정되지 않아도 중립 토큰으로 화면 구조와 상태 표현을 시작할 수 있습니다.
- API가 확정되지 않아도 응답을 `unknown`에서 검증하고 실제 계약으로 교체할 위치를 확인할 수 있습니다.
- 공통 컴포넌트는 반복되는 동작만 담고 API, 화면 이동과 업무 문구를 포함하지 않습니다.
- 사용처가 없는 Wrapper, 전역 type과 상태 저장 구조를 미리 만들지 않습니다.
- 각 예시에는 적용 조건, 파일 위치, 사용처와 테스트가 함께 있습니다.

Front-end만 먼저 준비하는 현재 상황에서도 이 범위는 유효합니다. Backend, 인증과 WebView Bridge 계약은 추측해서 공통 코드로 만들지 않고, 계약이 확정된 뒤 기능 가까이에서 시작하도록 남겨 두었습니다.

## 실제 저장소 생성 후 적용 순서

1. Next.js가 생성한 `tsconfig`, PostCSS 설정과 설치 package를 가이드 예시와 비교합니다.
2. 기존 설정을 교체하지 않고 Tailwind 토큰과 `components.json`의 필요한 부분만 병합합니다.
3. 실제 테스트 실행 도구를 확인한 뒤 공통 setup을 연결합니다.
4. 첫 서버 상태 기능이 생길 때 QueryClient와 Provider를 적용합니다.
5. 첫 실제 API 응답으로 검사 함수와 기능별 응답 검증 코드를 확인합니다.
6. 동일한 폼 동작이 반복될 때 `SubmitButton`과 `FormField`의 공통 위치를 결정합니다.
7. 실제 적용 결과에 맞춰 [공통 소스 적용 항목](./catalog.md)의 경로, 교체 지점과 미확정 항목을 갱신합니다.

## 평가의 한계

현재는 실제 애플리케이션 저장소가 없으므로 예시 코드를 실제 설치 버전에서 typecheck, test와 build까지 실행한 상태는 아닙니다. Markdown과 HTML의 구조, 링크와 코드 표시는 검증할 수 있지만, 실제 동작 여부는 저장소 생성 후 확인해야 합니다.

Next.js, shadcn과 설치 package가 생성하는 설정이 예시와 다를 수 있으므로 가이드 파일을 그대로 덮어쓰지 않습니다. 실제 source가 생긴 이후에는 실제 source를 기준으로 삼고, 가이드와 차이가 생기면 적용 이유와 함께 문서를 갱신합니다.

## 다음 검토 시점

현재 단계에서는 예시의 수를 더 늘리는 것보다 실제 저장소와 첫 기능에서 기존 예시를 검증하는 것이 우선입니다. 첫 기능을 적용한 뒤 반복되는 코드, 맞지 않는 경로와 빠진 테스트가 확인되면 그 근거로 공통 소스와 가이드를 보완합니다.

따라서 이 가이드는 프로젝트를 시작하기에 충분한 준비 자료로 평가합니다. 다만 프로젝트의 최종 구조나 제품 계약을 대신하지 않으며, 실제 사용처와 검증 결과를 통해 완성해 가는 기준으로 사용합니다.
