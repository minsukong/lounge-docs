# 더라운지 3.0 Figma 기획서 개발 기준 검토

> 상태: 검토용 초안  
> 작성 목적: 현재 Figma 기획자료가 기능 개발의 기준으로 사용되기 위해 보완해야 할 사항을 간략히 정리한다.

## 1. 검토 배경

현재 Figma에는 주요 화면과 대표 상태, 일부 사용자 흐름과 설명이 작성되어 있다. 따라서 화면 구성과 기능 방향을 이해하는 참고 자료로는 활용할 수 있다.

다만 화면이 작성되어 있다는 사실만으로 업무 규칙, 데이터 조건과 연동 방식까지 확정된 것은 아니다. 현재 자료를 안정적인 개발 기준으로 사용하려면 기능별 선행 협의와 보완이 필요하다.

## 2. 현재 확인된 주요 보완사항

- 화면별 목적, 진입 조건과 완료 조건이 충분히 구체화되지 않았다.
- 정상 화면 외에 로딩, 데이터 없음, 오류, 실패, 권한과 제한 상태가 부족하다.
- 화면 상태를 결정하는 업무 규칙과 우선순위가 명확하지 않다.
- 표시 데이터의 출처, 갱신 시점과 계산 주체를 확인하기 어렵다.
- Front-end와 Backend가 구현에 사용할 API 요청·응답, 인증과 오류 처리 기준이 연결되어 있지 않다.
- 화면 이동과 기능 분기는 표현되어 있으나 분기 조건과 최종 처리 결과가 충분히 정의되지 않았다.
- 확정, 검토 중, 미정 항목이 명확히 구분되지 않아 각 파트가 서로 다른 전제로 작업할 수 있다.
- 글로벌 주요 4개국 대상 서비스에 필요한 국가별 가입 조건, 외국인 회원, 언어, 전화번호·OTP, 약관과 개인정보 처리 기준은 별도 확인이 필요하다.

## 3. 개발 일정에 미치는 영향

현재 자료를 기준으로 공통 레이아웃, 디자인 시스템과 일부 정적 UI는 선행 작업할 수 있다. 그러나 업무 규칙과 Backend 연동이 확인되지 않은 기능을 완성된 범위로 선개발하면 다음 문제가 발생할 수 있다.

- API와 데이터 구조 확정 후 Type, 상태 관리와 화면 로직 재작업
- 누락된 오류·예외 상태 추가에 따른 UI 및 테스트 수정
- Front-end, Backend와 QA의 완료 기준 불일치
- 화면은 구현됐지만 실제 연동과 운영 검증이 지연되는 상황
- 선행 구현이 일정 단축이 아니라 재개발과 일정 변동으로 이어질 가능성

따라서 미확정 기능의 선행 구현은 확정 개발과 구분하고, 가정과 변경 가능 범위를 작업 항목에 명시해야 한다.

## 4. 개발 착수 전 필요한 최소 조치

1. 기능별 업무 규칙과 정상·예외 상태를 확인한다.
2. 미확정 항목마다 확인 담당과 목표일을 지정한다.
3. 기획, Front-end와 Backend가 기능별 데이터 및 API 처리 방식을 협의한다.
4. WebView 또는 Native 연동이 필요한 기능은 요청·응답과 실패 처리 기준을 함께 정한다.
5. 글로벌 가입 기능은 국가별 조건과 공통·개별 처리 범위를 구분한다.
6. 위 결과를 Figma, API 명세와 WBS에 같은 기준으로 반영한다.

## 5. 종합 의견

현재 Figma 기획자료는 화면과 대표 흐름을 공유하는 자료로는 가치가 있다. 다만 업무 규칙, 데이터, 예외 처리와 파트 간 협의 결과가 충분히 연결되지 않아 현재 상태만으로 개발 완료 범위와 일정을 확정하기는 어렵다.

전체 개발을 중단하기보다 협의가 끝난 기능부터 순차적으로 진행하고, 미확정 기능은 필요한 결정과 일정 영향을 별도로 관리하는 방식이 필요하다.

## 6. 검토 범위와 한계

이번 검토는 전체 Figma 파일에 대한 전수 검사가 아니라 다음 대표 영역을 확인한 결과다.

- 홈 로그인 후 개인화 영역
- 아이디·비밀번호 찾기 흐름
- 아이디 찾기 화면과 OTP 관련 상태

다른 화면에도 동일한 기준을 적용해 기능별 확정 여부를 추가 확인해야 한다. 이 문서는 특정 개인이나 조직의 역량 또는 책임을 평가하지 않으며, 현재 자료에서 확인 가능한 개발 준비 상태만을 대상으로 한다.
