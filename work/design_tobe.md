# shadcn 기반 디자인 작업 기준

## 1. 디자인 작업 방향

더라운지 3.0은 **프로젝트에서 사용하는 shadcn 컴포넌트를 디자인의 출발점으로 삼는다.** 디자인팀도 같은 컴포넌트 이름·종류·크기·의미 토큰을 사용해 화면을 구성한다.

버튼·입력창·팝업 등의 공통 요소를 처음부터 새로 설계하기보다, 제공되는 컴포넌트를 조합하고 서비스에 필요한 색상·콘텐츠·배치를 적용한다. 기존 자체 공통 디자인을 재현하는 작업을 기준으로 삼지 않는다.

화면에 필요한 표현이 기존 구성으로 해결되지 않으면 해당 부분만 디자인·개발이 함께 확장한다. 새 종류나 토큰을 추가할 때에는 이름과 적용 범위를 함께 정해 Figma와 코드에 동일하게 반영한다.

## 2. base-nova 이해하기

`base-nova`는 **동작을 담당하는 기반과 외형을 정하는 스타일을 조합한 이름**이다.

| 구분 | 의미 | 디자인 작업에서 알아둘 점 |
| --- | --- | --- |
| `base` | Base UI를 기반으로 컴포넌트를 구성함 | Dialog의 포커스 이동, Checkbox의 선택 등 상호작용을 담당한다. 기본 색상이나 작은 크기를 뜻하는 이름이 아니다. |
| `nova` | shadcn의 외형 스타일 중 하나 | 컴포넌트의 여백·배치·크기 등 시각적 기본 구성을 제공한다. 브랜드 색상이나 light·dark 모드 이름이 아니다. |
| `neutral` | 프로젝트 초기 테마의 기본 색상 계열 | 현재 코드의 중립 색상 출발점이다. 더라운지 브랜드 색상 매핑이 확정됐다는 뜻은 아니다. |
| CSS 변수 방식 | `primary`, `background` 같은 의미 토큰으로 색상을 적용함 | 같은 역할의 색상을 바꾸면 여러 컴포넌트에 함께 반영한다. |

Base UI는 동작을 제공하는 기반이고, shadcn은 여기에 스타일과 조합 구조를 적용한 컴포넌트 코드를 제공한다. 개발에서는 이 코드를 프로젝트 안에서 관리하므로 서비스에 맞게 조정할 수 있다. [shadcn 공식 구성 설명](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/README.md)

### 디자인팀이 맞출 기준

- Figma 키트를 사용한다면 Nova 스타일과 Base UI 기반 구성에 대응하는지 확인한다. `shadcn`이라는 이름만 같다고 동일한 구성으로 보지 않는다.
- Base UI와 Radix UI는 다른 기반이다. Radix 기반 키트도 외형은 활용할 수 있지만, 컴포넌트 구성·상태가 우리 코드와 대응하는지 먼저 확인한다.
- 현재 프로젝트에는 모바일 조작 영역과 호환성을 위해 조정한 코드가 있다. **공식 Nova 원본보다 프로젝트의 실제 컴포넌트와 Storybook을 우선한다.**
- Nova를 선택했다고 폰트·브랜드 색상·모든 수치가 자동 확정되지는 않는다. 공통값을 바꿀 때에는 개별 화면마다 수정하지 않고 공통 컴포넌트·토큰에 반영한다.

예를 들어 현재 버튼은 기본형과 작은 크기 모두 최소 높이가 44px이다. Figma 키트의 작은 버튼 높이가 더 낮더라도 그대로 적용하지 않고 현재 프로젝트 기준과 맞춘다. 이 문서의 px 환산은 기본 글자 크기 16px 기준이다.

## 3. 공통 컴포넌트와 이름

### 현재 사용할 수 있는 구성

| 구분 | 프로젝트 컴포넌트 | 사용 기준 |
| --- | --- | --- |
| 행동 | `Button` | 버튼 종류와 크기를 선택해 사용 |
| 입력 | `Input`, `Textarea`, `Label` | 기본·포커스·오류·비활성·읽기 전용을 구분 |
| 선택 | `Checkbox` | 선택·미선택·부분 선택·비활성 등을 사용 목적에 맞게 확인 |
| 정보 | `Card`, `Badge` | 같은 역할의 카드·배지는 공통 구성을 재사용 |
| 팝업 | `Dialog`, `Sheet` | 제목·설명·본문·행동·닫기 영역을 구분 |
| 상태 | `Skeleton`, `StatusPanel` | 로딩·빈 화면·에러·오프라인 표현에 사용 |

`StatusPanel`은 프로젝트에서 만든 상태 표현이다. 나머지 컴포넌트도 설치 후 프로젝트에 맞게 조정한 부분이 있으므로 현재 구현을 기준으로 확인한다.

Select·RadioGroup·Switch·Tabs 등은 실제 화면에서 필요해지면 같은 `base-nova` 기준으로 추가한다. 아직 프로젝트에 없는 컴포넌트를 이미 구현된 것으로 전달하지 않는다.

### Button 이름 대응

| 속성 | 공통으로 사용하는 값 |
| --- | --- |
| `variant` | `default`, `secondary`, `outline`, `ghost`, `destructive`, `link` |
| `size` | `default`, `sm`, `lg`, `icon`, `icon-sm` |

Figma에서도 `Button`의 `variant`와 `size`에 같은 값을 사용한다. 주요 버튼을 표현하더라도 variant 이름을 별도로 `primary`로 바꾸지 않는다. **버튼 종류는 `default`, 사용하는 색상 역할은 `primary`**로 구분한다.

기본·hover·누름·포커스·비활성·로딩 등의 상태도 디자인에서 확인한다. Figma에서 상태를 표현하는 속성이 코드의 동일한 이름의 속성을 의미하지는 않는다. 로딩처럼 추가 구현이 필요한 상태는 개발과 대응 방식을 확인한다.

현재 `destructive` 버튼은 위험 색상의 테두리·글자와 기본 배경을 사용하는 형태다. 다른 키트의 채움형 위험 버튼을 기본값으로 혼용하지 않는다.

Dialog와 Sheet는 서로 다른 컴포넌트로 구분한다. 현재 Sheet는 `top`, `right`, `bottom`, `left` 방향을 지원한다. 아래에서 열리는 Sheet에 끌어서 닫기 같은 Drawer 동작이 자동 포함된 것으로 가정하지 않는다.

## 4. 의미 토큰과 네이밍

색상은 shadcn의 **역할 이름을 디자인과 개발에서 함께 사용**한다. Figma에서 역할별 변수를 만들고 컴포넌트에 연결하며, 코드에서는 같은 역할의 CSS 변수와 연결한다.

| Figma 의미 토큰명 | 사용 역할 | CSS 변수 | 코드 사용 예시 |
| --- | --- | --- | --- |
| `background` / `foreground` | 화면 배경 / 기본 글자·아이콘 | `--background` / `--foreground` | `bg-background`, `text-foreground` |
| `card` / `card-foreground` | 카드 배경 / 카드 본문 | `--card` / `--card-foreground` | `bg-card`, `text-card-foreground` |
| `popover` / `popover-foreground` | 떠 있는 영역의 배경 / 본문 | `--popover` / `--popover-foreground` | `bg-popover`, `text-popover-foreground` |
| `primary` / `primary-foreground` | 주요 행동 배경 / 그 위의 글자·아이콘 | `--primary` / `--primary-foreground` | `bg-primary`, `text-primary-foreground` |
| `secondary` / `secondary-foreground` | 보조 행동 배경 / 본문 | `--secondary` / `--secondary-foreground` | `bg-secondary`, `text-secondary-foreground` |
| `muted` / `muted-foreground` | 약한 배경 / 보조 문구 | `--muted` / `--muted-foreground` | `bg-muted`, `text-muted-foreground` |
| `accent` / `accent-foreground` | 상호작용 강조 배경 / 본문 | `--accent` / `--accent-foreground` | `bg-accent`, `text-accent-foreground` |
| `destructive` | 위험 행동·오류 색상 | `--destructive` | `text-destructive`, `border-destructive` |
| `border` | 기본 테두리 | `--border` | `border-border` |
| `input` | 입력 테두리 | `--input` | `border-input` |
| `ring` | 포커스 표시 색상 | `--ring` | 포커스 스타일에 적용 |

Figma의 의미 토큰명에는 CSS용 접두사 `--`나 Tailwind용 접두사 `bg-`, `text-`를 붙이지 않는다. 컬렉션·모드를 나누더라도 역할 이름은 유지한다. 이 표는 앞으로 맞출 공통 이름이며, 현재 Figma에 모두 생성·연결돼 있다는 뜻은 아니다.

shadcn은 배경 역할과 그 위에 놓이는 글자·아이콘 역할을 짝으로 사용한다. 예를 들어 주요 버튼에는 `primary`와 `primary-foreground`를 함께 적용한다. `primary`라는 이름이 특정 파란색 값 자체를 의미하지는 않는다. [shadcn 공식 테마 기준](https://ui.shadcn.com/docs/theming)

### 원시 팔레트와 의미 토큰 구분

기존 원시 색상은 역할 토큰에서 참조하는 재료로 활용한다. 원시 팔레트 이름과 컴포넌트 역할 이름을 혼용하지 않는다.

| 단계 | 예시 | 현재 상태 |
| --- | --- | --- |
| 원시 팔레트 | Figma export 경로 `Brand/blue500` | 전달된 색상값 존재 |
| 생성된 원시 CSS 변수 | `--lounge-brand-blue-500` | 코드 연결됨 |
| 의미 토큰 | `primary` | 브랜드 팔레트와의 연결은 미확정 |
| 컴포넌트 | `Button`, `variant=default` | 현재 의미 토큰을 사용함 |

`primary`를 Blue 500에 연결할지는 실제 버튼·글자 대비를 확인해 정한다. 이미 전달된 색상을 활용하되 이름이 비슷하다는 이유만으로 자동 대응시키지 않는다.

성공·경고·안내·Dim 등 기본 의미 토큰만으로 표현하기 어려운 반복 요구는 필요한 시점에 이름과 용도를 함께 추가한다. 같은 역할에 디자인과 개발이 서로 다른 이름을 만들지 않는다.

## 5. 값의 확정 상태와 변경 방법

| 항목 | 현재 상태 | 적용 방법 |
| --- | --- | --- |
| shadcn 기반·스타일 | `base-nova` | 같은 구성으로 디자인 시작 |
| 원시 색상 | light·dark export와 코드 연결 있음 | 기존 팔레트 활용 |
| 의미 색상 | 코드에 neutral 초안 있음 | 현재값과 최종 브랜드 적용값을 구분 |
| light·dark | 원시 팔레트는 같은 값, 의미 테마는 서로 다른 값 | dark 디자인 범위를 별도 확인. 현재 dark 미리보기를 최종 디자인으로 보지 않음 |
| 폰트·간격·라운드 | 현재 코드에 기본값 있음 | 프로젝트 컴포넌트 기준으로 시작하고 필요한 공통 변경만 합의 |
| 자동 토큰 변환 | 현재 원시 색상에 적용 | 의미 토큰·폰트·간격까지 자동 변환된다고 가정하지 않음 |

Figma의 반복되는 값은 Variables와 공통 스타일에 연결한다. 디자인 토큰의 생성·수정·삭제는 프로젝트의 Tokens Studio 원본 관리 기준을 따르고, Figma Variables와의 적용 관계를 맞춘다. 생성된 코드 파일을 직접 수정해 디자인과 다른 값을 만들지 않는다.

폰트·간격·크기·라운드는 기존 컴포넌트의 체계를 우선한다. 기본값으로 화면 구성을 시작할 수 있으며, 공통값을 바꾸는 경우에는 여러 화면에 미치는 영향을 확인한다. 폰트·간격 등 추가 토큰의 이름과 변환 방식은 디자인·개발이 함께 정한다.

## 6. 화면 구성과 상태 디자인

디자인팀은 공통 요소의 반복 재설계보다 **컴포넌트 조합, 정보의 우선순위, 서비스 콘텐츠, 반응형 배치**에 집중한다.

- 같은 컴포넌트와 같은 역할은 화면이 달라도 동일한 토큰·종류·크기를 사용한다.
- 화면 너비에 따른 모바일·PC 배치와 앱 WebView·일반 브라우저의 차이를 구분한다. 좁은 화면이라는 이유만으로 앱 전용 헤더나 하단 메뉴를 적용하지 않는다.
- 긴 문구·여러 줄 Label·큰 글자·키보드 표시·스크롤·안전 영역을 대표 화면에서 확인한다.
- 기본·포커스·오류·비활성·로딩 상태를 빠뜨리지 않고, 오류는 색상과 함께 문구로 전달한다.
- 전체 화면 로딩과 기존 내용을 유지하는 갱신을 구분한다. 빈 화면·오프라인에서는 필요한 안내와 행동을 함께 배치한다.
- Dialog·Sheet의 닫기 허용 여부처럼 업무에 따라 달라지는 동작은 화면에 표시한다. 기반 컴포넌트의 키보드·포커스 동작은 유지한다.

지원 환경에서는 핵심 정보·입력·이동이 유지돼야 한다. 최신 시각 효과가 필요한 경우 Safari 15 등 프로젝트 지원 환경에서의 대체 표현을 개발과 확인한다.

## 7. 디자인 전달과 확인 순서

1. 개발에서 현재 컴포넌트·토큰 목록과 Storybook을 공유한다.
2. 디자인팀에서 사용할 shadcn 키트의 Nova 스타일과 우리 컴포넌트를 대조한다.
3. Button·Input·Checkbox·Card·Badge·Dialog·Sheet 표본을 같은 이름과 토큰으로 맞춘다.
4. 공통으로 바꿀 브랜드 색상·폰트·수치를 정하고 Figma와 코드 양쪽에 반영한다.
5. 맞춘 컴포넌트의 인스턴스로 실제 화면을 구성하고 모바일·PC·앱 환경에서 확인한다.

전달 시에는 컴포넌트명, `variant`·`size`, 사용한 의미 토큰, 기본 구성에서 달라진 부분만 명확히 표시한다. 기본 컴포넌트로 해결되는 항목을 화면마다 다시 정의하지 않는다.

처음에는 버튼·입력·팝업이 들어간 대표 화면으로 Figma와 Storybook을 대조한다. 공통 구성과 변경값을 맞춘 뒤 나머지 화면에 확장한다.
