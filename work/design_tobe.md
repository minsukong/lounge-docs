# shadcn 기반 공통 UI 디자인 협의 항목

## 1. 역할별 색상 연결

전달된 팔레트에서 아래 역할에 사용할 색을 정한다. 개발에서 이 역할을 shadcn의 CSS 변수에 연결한다.

| 디자인에서 정할 역할                    | shadcn 연결                          |
| --------------------------------------- | ------------------------------------ |
| 주요 버튼·강조 행동과 그 위의 글자색    | `primary` / `primary-foreground`     |
| 보조 버튼과 그 위의 글자색              | `secondary` / `secondary-foreground` |
| 화면 배경과 기본 본문                   | `background` / `foreground`          |
| 카드 배경과 내용                        | `card` / `card-foreground`           |
| 팝업·선택 목록 배경과 내용              | `popover` / `popover-foreground`     |
| 약한 배경과 보조 문구                   | `muted` / `muted-foreground`         |
| 메뉴 등의 hover·강조 배경과 내용        | `accent` / `accent-foreground`       |
| 삭제·위험 행동, 입력 오류               | `destructive`와 오류 표현 기준       |
| 일반 구분선·입력창 테두리·키보드 포커스 | `border` / `input` / `ring`          |

`foreground`는 해당 배경 위에 표시할 글자·아이콘 색을 뜻한다.

성공·경고·안내처럼 추가로 필요한 역할은 실제 사용처를 확인해 프로젝트 토큰으로 정한다. 토큰 이름과 코드 연결은 개발에서 관리한다.

## 2. 버튼 종류와 크기

현재 구현된 버튼 종류를 실제 디자인에서 어떤 용도로 사용할지 정한다.

| 버튼 종류     | 합의할 내용                                   |
| ------------- | --------------------------------------------- |
| `default`     | 가장 중요한 행동. 배경색·글자색·사용 우선순위 |
| `secondary`   | 보조 행동. 주요 버튼과 함께 놓였을 때의 구분  |
| `outline`     | 테두리형 버튼의 사용처와 테두리·배경          |
| `ghost`       | 배경이 약하거나 없는 행동 버튼의 사용처       |
| `destructive` | 삭제·취소 등 위험 행동을 어떤 형태로 표현할지 |
| `link`        | 본문·화면 안의 링크 표현과 밑줄 기준          |

함께 정할 크기 기준:

- 기본·작은·큰 버튼의 높이와 좌우 여백
- 글자 크기·굵기, 아이콘 크기와 글자 사이 간격
- 아이콘 전용 버튼 크기
- 라운드와 전체 너비 버튼의 사용 기준

디자인에 필요하지 않은 종류를 모두 사용하거나 추가할 필요는 없다.

## 3. 컴포넌트별 모양과 상태

| 대상                   | 합의할 내용                                                 |
| ---------------------- | ----------------------------------------------------------- |
| **Input·Textarea**     | 높이·라운드·배경·테두리, Label·설명·오류 문구의 위치와 간격 |
| **Checkbox**           | 크기·선택 표시, Label과의 간격, 오류·비활성 표현            |
| **Card**               | 배경·테두리·그림자, 내부 여백, 제목·본문·행동 영역 간격     |
| **Badge**              | 상태별 색상·글자·크기·라운드와 사용 의미                    |
| **Dialog·Sheet**       | 폭·여백·라운드, 제목·본문·버튼 배치, 닫기 버튼과 배경 Dim   |
| **Skeleton·상태 화면** | 로딩 형태, 빈 화면·에러·오프라인의 아이콘·문구·버튼 배치    |

상호작용이 있는 컴포넌트는 필요한 **기본·hover·누름·포커스·선택·비활성·오류·로딩** 상태를 함께 확인한다.

shadcn에서 제공하는 포커스·키보드·접근성 동작을 유지하면서 디자인을 적용한다. 변경이 필요한 동작은 디자인과 개발이 함께 확인한다.

## 4. 공통 수치와 예외

- 버튼·입력창·카드·팝업의 라운드를 어느 단계로 통일할지
- 제목·본문·보조 문구·Label·버튼의 글자 크기·굵기·행간
- 컴포넌트 내부 여백과 항목 사이 간격
- 테두리 두께·그림자·아이콘 크기
- 모바일과 PC에서 달라지는 크기·배치
- 공통 컴포넌트의 새 종류가 필요한 경우와 화면별 배치로 해결할 경우

합의한 값은 CSS 변수와 Tailwind 기준에 연결한다. 공통 컴포넌트의 예외는 실제 사용 이유가 있을 때 추가한다.

## 5. 합의 결과 확인

대표 버튼·입력창·카드·Dialog·Sheet·로딩·에러 화면을 **Figma와 Storybook에서 비교**한다.

확인할 결과는 다음과 같다.

- 같은 역할의 색상과 크기가 여러 컴포넌트에서 일관적인가
- 주요·보조·위험 행동이 구분되는가
- 글자·테두리·포커스와 오류 상태가 잘 보이는가
- 긴 문구와 모바일 너비에서도 사용할 수 있는가
- 디자인 차이를 토큰 수정으로 해결할지, 컴포넌트 수정으로 해결할지 정해졌는가

개발에서 역할별 토큰 대응표와 컴포넌트별 적용 결과를 정리하고, 디자이너는 실제 표시 결과를 확인한다.
