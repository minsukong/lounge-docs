# 디자인 토큰·공통 UI 협의 항목

## 1. 먼저 맞출 방향

- 디자인은 Figma에서, 공통 UI 구현은 shadcn/ui와 Tailwind CSS로 진행한다.
- 기존 컴포넌트를 출발점으로 사용하되, 모양과 스타일은 합의한 디자인에 맞춘다.
- 색상·폰트·간격 같은 공통 기준은 토큰으로 관리한다.
- 디자이너는 디자인의 역할과 의도를 정하고, 개발자는 이를 토큰·CSS·컴포넌트에 연결한다.

## 2. 함께 결정할 내용

| 항목                     | 의논할 내용                                                                              |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| **색상 역할**            | 주요 버튼, 보조 버튼, 본문, 보조 문구, 화면 배경, 카드, 구분선에 어떤 색을 사용하는가    |
| **브랜드 기준색**        | 주요 행동에 Blue 500과 Blue 600 중 무엇을 사용하는가. 버튼 위 글자색과 링크색은 무엇인가 |
| **상태 색상**            | 오류·경고·성공·안내 색상을 글자·아이콘·배경·테두리에 각각 어떻게 사용하는가              |
| **타이포그래피**         | 기본 폰트, 굵기, 제목·본문·보조 문구의 크기와 행간                                       |
| **간격·크기**            | 화면 좌우 여백, 영역·항목 사이 간격, 버튼·입력창 높이, 아이콘 크기                       |
| **라운드·테두리·그림자** | 버튼·입력창·카드·팝업의 모서리, 테두리 두께와 그림자 사용 기준                           |
| **상호작용 상태**        | 기본·누름·선택·비활성·포커스·입력 오류·로딩 상태의 표현                                  |
| **공통 상태 화면**       | 로딩·빈 화면·에러·오프라인의 문구, 아이콘, 배치, 다시 시도 버튼                          |
| **Light·Dark**           | 현재는 같은 색을 사용하고, 이후 dark를 변경할 때 유지할 역할과 변경할 값                 |

색상 조합은 실제 글자와 컴포넌트에 적용해서 가독성도 함께 확인한다. 팔레트만 보고 최종 확정하지 않는다.

## 3. 토큰 구조와 담당

토큰은 다음 관계로 연결한다.

**원시 값 → 화면에서의 역할 → 컴포넌트 사용**

예: `Blue 600 → 주요 행동 색상 → 기본 버튼 배경`

- **디자인 담당:** 원시 값, 역할별 사용 의도, 대표 화면과 상태 확인
- **개발 담당:** 의미 토큰 이름, shadcn 변수 매핑, CSS·Tailwind 변환, 컴포넌트 적용
- **공동 확인:** 대표 UI의 시각 결과, 상태별 가독성, 변경 영향

디자인에서는 “주요 행동 색상”처럼 이해하기 쉬운 이름을 사용하고, 개발에서 `primary` 같은 구현 이름과 대응표를 관리할 수 있다.

## 4. 저장소 동기화 운영

- Tokens Studio가 연결된 저장소·브랜치·파일 경로를 확인한다.
- 토큰 원본을 어디에서 수정할지, 누가 변경을 반영할지 정한다.
- 디자인과 개발이 같은 토큰을 동시에 수정했을 때 조정할 담당을 정한다.
- 저장소에서 가져오는 단계와 Figma Variables·Styles 및 화면에 적용하는 단계를 구분한다.
- CSS는 토큰 원본에서 생성하고, 생성 결과를 따로 수정해 값이 갈라지지 않게 한다.
- 기존 Figma 변수·컴포넌트 연결을 유지할 수 있도록 이름 변경·삭제는 함께 확인한다.

## 5. 첫 합의의 완료 기준

처음부터 모든 화면을 확정할 필요는 없다. 다음 표본을 Figma와 Storybook에서 나란히 확인한다.

- 주요·보조·위험 버튼
- 기본·포커스·오류·비활성 입력창
- 카드와 Dialog·Sheet
- 로딩·빈 화면·에러 화면

**역할별 색상, 폰트, 간격, 라운드와 주요 상태가 합의되고 표본 UI에서 확인되면 첫 기준으로 삼는다.** 미정인 항목은 목록으로 남기고, 확인된 범위부터 적용한다.
