## 1. 읽는 방법

A에서 확인한 미확정 질문이 웹·앱 작업에서 어떤 화면·로직·연동·검증에 영향을 주는지 기록한다. 답이 바뀌면 영향도 바뀐다. "협의 안 됨"만으로 모든 준비 작업을 중단으로 기록하지 않는다.

---

## 2. RC별 영향

### RC-04-001 이용권·주문 상태 용어 정리 표 부재

| 영향 대상 | 내용 |
|---|---|
| 이용권 목록 탭 분기 | "사용가능" 탭에 포함될 상태 집합, "사용 이력" 탭의 상태 정의가 표 기준. 표 없으면 탭 필터 로직 구현 불가 |
| 주문 목록 탭 | "결제/예약" vs "취소/교환" 탭의 상태 매핑 불가 |
| 주문 상세 버튼 노출 | 취소/교환/재구매 버튼의 enabled 조건이 상태 정의에 의존 |
| 상태 변경 이력 UI | 사용이력 상세의 상태 타임라인 표시 항목·순서 정의 불가 |
| 검증 | 상태 전이 케이스 테스트 불가 |

**현재 상태:** 표 내용 미확인(TABLE 추출 불가 + PDF 외부 참조). 확인 전에는 상태 enum·필터 조건을 확정할 수 없음.

### RC-04-002 이용권 목록 탭 명칭 불일치

| 영향 대상 | 내용 |
|---|---|
| 화면 구현 | 탭 label 텍스트, aria-label, i18n 키 |
| IA·네비게이션 | Breadcrumb, 화면 경로 표기 |
| 테스트 | 탭 이름 기반 E2E 테스트 |

**현재 상태:** 화면 "사용가능" vs 설명 "보유 이용권". 어느 쪽이 최종인지 확인 전까지 화면 기준("사용가능")으로 작업하되, 변경 가능성을 열어둠.

---

### RC-04-003 C030101/C030102 탭 구조 관계

| 영향 대상 | 내용 |
|---|---|
| 화면 수·라우팅 | 별도 화면 2개 vs 1개 화면 내 탭 분기 → 라우트 수, 컴포넌트 구조 달라짐 |
| 데이터 조회 | 구매 이용권 vs 제휴카드 무료 이용권 API 분리 여부 |
| IA | 마이페이지 메뉴에서 "이용권함" 진입 시 어느 화면으로 연결되는가 |

**현재 상태:** 화면 코드는 분리(C030101/C030102)이나 UI 탭 구조 동일. 확인 전에는 별도 화면 2개로 가정하되, 통합 가능성 배제 안 함.

### RC-04-004 무료 이용권 취소와 카드사 연동

|---|---|

**현재 상태:** 기획에 취소 가능 조건·문구만 있음. 연동 계약 미확인.

### RC-04-005 이용권 등록 번호 형식

| 영향 대상 | 내용 |
|---|---|
| 입력 유효성 | 16자리/8자리 판별 로직, 입력 필드 maxlength |

**현재 상태:** "16자리 또는 8자리"만 명시. 판별 기준·오류 처리 미정의.
