## 1. 목적과 읽는 방법

현재 기획만 전달받은 작업자가 추가 질문 없이 동일한 결과를 만들 수 있는지 확인하기 위한 기록이다. 기획자 평가나 책임 판단을 목적으로 하지 않는다.

초안 작성자가 기록한 프레임 ID·문구·IA 대조 결과를 보존한다. 아래의 “원본 관찰”과 “IA 원본 대조 결과”는 초안 보고를 뜻하며, 독립 원본 확인을 마친 것으로 해석하지 않는다.

초안은 02. 메인에 화면 설계와 리서치·전략 자료가 섞여 있다고 보고했다. 아래 표의 화면 설계만 검토 대상으로 기록하며, 설명이 거의 없는 PC·태블릿은 RC-02-012에서 작성 중·검토 보류로 남긴다. `OLD`·`PC old`는 제외하며 하위 내용은 근거로 사용하지 않는다.

"이 페이지에 없다"를 "프로젝트 전체에서 미정의"로 확대하지 않는다. 특히 여정 등록·월렛·알림은 다른 페이지와 01. 공통에 정의가 있다.

## 3. 검수 분류와 상태

| 분류 | 확인할 내용 |
|---|---|
| [정책] | 대상·조건·제한·우선순위가 정의되어 있는가 |
| [Flow] | 진입·성공·실패·취소·복귀와 다음 화면이 연결되어 있는가 |
| [화면/상태] | 상태별 노출·문구·입력·버튼 동작을 재현할 수 있는가 |
| [데이터/API] | 필요한 데이터, 요청·응답, 오류와 세션 처리를 합의했는가 |
| [Native/Web] | Flutter·WebView·BE 등 처리 주체와 전달 경계가 정의되어 있는가 |
| [변경] | 기준 변경, 적용 범위와 재작업 여부를 추적할 수 있는가 |

상태는 `후보 → 원본 대조 → 사용자 검토 → 확인 요청 → 답변 수신 → 반영 확인 → 종료`로 관리한다. 현재는 초안 보고 기준으로 문서 논리만 검수했고, 독립 원본 대조는 대기 중이다. 실제 요청을 보내기 전에는 '확인 요청 완료'로 표시하지 않는다.

**Backend 협의 전제(2026-10-07 사용자 확인):** 현재 Backend 협의가 충분히 이루어지지 않아 연동 기준의 합의 여부를 확인해야 하는 상태다. 사용자에게 보이는 조건·흐름은 **기획 확인**, 데이터·인증·오류·상태 전달·처리 주체는 **Backend 협의 필요**로 구분한다. API·문서·구현 부재나 모든 항목의 미합의를 뜻하지 않으며, 기존 자료·합의 근거를 항목별로 확인한다. 이 문서에서 기술 계약이나 담당을 정하지 않는다.

## 5. 상세 항목

### RC-02-001 — 홈 화면의 플랫폼·화면구분 기준

- **원본 관찰:** APP IA의 메인 행은 `FO-MAI-A010000`(로그인 전), `FO-MAI-A020000`(로그인 후), `A020101`, `A020102`, `A020201`, `A020202`, `A020203`, `A020300`, `A020401`을 **Native**로, `A010100`·`A010200`·`A020402`를 webview로 배치한다. WEB IA는 같은 12개 코드를 모두 webview로 두되 화면구분이 다르다.
- **IA 원본 대조 결과(같은 코드 기준):**

| 코드 | APP IA | WEB IA |
|---|---|---|
| `A010000` | page · Native | page · webview(비회원) |
| `A010100` | page · webview | **Layer** · webview(비회원) |
| `A010200` | page · webview | **Layer** · webview(비회원) |
| `A020000` | page · Native | page · webview(회원) |
| `A020101` | page · Native | **content** · webview(회원) |
| `A020102` | **Layer** · Native | **content** · webview(회원) |
| `A020201` | Layer · Native | Layer · webview(회원) |
| `A020202` | page · Native | **content** · webview(회원) |
| `A020203` | content · Native | content · webview(회원) |
| `A020300` | content · Native | **Layer** · webview(회원) |
| `A020401` | **Layer** · Native | **page** · webview(회원) |
| `A020402` | content · webview | page · webview(공통) |

  WEB IA에는 이 외에 코드가 비어 있는 행(제휴카드 상세, 국가 선택, 공항위치 감지 안내)이 있다.
- **확인되지 않은 부분:** APP와 WEB은 각각 하이브리드 앱과 반응형 홈페이지의 별도 과업이다. 같은 코드의 플랫폼·page/Layer/content 차이는 의도된 구성일 수 있다. 각 Figma 프레임이 어느 시트+코드에 대응하는지, 앱 안의 Native/WebView 영역이 어떻게 연결되는지 확인한다.
- **작업 영향:** 플랫폼별 Figma 대응과 앱 내부 연결이 확인되면 화면 조립·이동·헤더 및 GNB 연결 범위를 구체화할 수 있다. IA 차이만으로 주체 미정이나 화면 충돌을 단정하지 않는다. 공통 화면의 대응 기준은 RC-01-007과 이어진다.
- **임시 가정:** 없음.
- **변경/재작업 가능성:** 플랫폼별 대응이나 앱 내부 배치가 실제로 변경되면 해당 화면 연결에 영향이 있을 수 있다. 두 과업 중 한쪽 화면이 사라진다고 가정하지 않는다.

### RC-02-002 — 화면 코드와 상태 프레임의 대응

- **원본 관찰:** `FO-MAI-A020000` 이름표가 붙은 프레임이 두 개다. `40004496:26451`은 "홈(로그인 후) 카드 x, 여정 x", `40004496:26452`는 "홈(로그인 후) 카드 o, 여정 o"이다. 앞에는 `1 개인화 영역 (My)`, `1-1 보유 제휴카드 / Default) 비로그인 상태와 동일`, `1-2 내 여정 (가제)`만 적혀 있고, 뒤에는 `A020102`(제휴카드 등록), `A020203`(여정 등록) 이름표가 함께 있다.
- **IA 원본 대조 결과:** APP IA는 `A020102`를 "제휴카드 등록", `A020203`를 **"여정 등록 완료"**로 둔다. Figma의 `A020203` 이름표는 여정 등록 영역에 붙어 있다.
- **확인되지 않은 부분:** 같은 A020000 프레임은 하나의 홈을 상태별로 보여준 것일 수 있다. A020102·A020203이 영역 또는 연결 화면을 뜻하는지와 카드 o/여정 x, 카드 x/여정 o 조합의 기존 정의 위치를 확인한다. 이름 차이 자체를 코드 충돌로 보지 않는다.
- **작업 영향:** 상태별 노출과 CTA 동작이 확인되면 구현·검증 범위를 정리할 수 있다. 상태 조합 수가 곧 별도 화면 수나 개발 분기 수라는 의미는 아니다.
- **임시 가정:** 없음.
