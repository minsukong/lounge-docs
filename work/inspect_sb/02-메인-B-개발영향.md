## 1. 확인할 내용과 작업 전제

초안에는 홈 상태, 팝업 트리거와 일부 전시 규칙이 기록되어 있다. 아래는 그 관찰을 토대로 답에 따라 달라질 웹·앱 작업 범위를 정리한 것이다.

- **플랫폼별 대응:** APP는 하이브리드 앱, WEB은 반응형 홈페이지다. 시트+코드와 Figma 대응 및 앱 내부 Native/WebView 연결을 확인한다(RC-02-001).
- **상태와 이동:** 반복된 홈 코드는 상태 표현일 수 있다. 여정 안내·입력 화면의 역할과 CTA 목적지를 확인한다(RC-02-002, RC-02-003, RC-02-009).
- **전시 데이터:** 퀵 메뉴의 BO 관리는 명시되어 있다. 항목 수·정렬·NEW 적용 기준과 다른 영역의 관리·데이터 계약을 확인한다(RC-02-007, RC-02-008).
- **팝업 연결:** 겹치는 트리거의 처리와 위치 동의·도착 확인 단계의 관계를 확인한다. 하나만 노출하는 정책을 정한 것은 아니다(RC-02-004, RC-02-005).

**Backend 협의 전제(2026-10-07 사용자 확인):** 현재 Backend 협의가 충분히 이루어지지 않아 연동 기준의 합의 여부를 확인해야 하는 상태다. 사용자에게 보이는 조건·흐름은 **기획 확인**, 데이터·인증·오류·상태 전달·처리 주체는 **Backend 협의 필요**로 구분한다. API·문서·구현 부재나 모든 항목의 미합의를 뜻하지 않으며, 기존 자료·합의 근거를 항목별로 확인한다. 발송·권한·앱 진입은 앱 담당과도 연결해 확인한다. 협의 부족만으로 모든 화면 작업을 중단으로 기록하지 않는다. 승인된 임시 가정은 없다.

## 2. 화면 코드와 화면구분

아래 표는 초안 작성자가 보고한 IA 값이다. APP와 WEB의 코드가 같아도 시트가 다르면 별도 과업의 화면이며, 구성 차이는 의도된 것일 수 있다. Figma와의 대응 및 값은 독립 재검증 전이다.

| 화면 | 코드 | APP IA | WEB IA |
|---|---|---|---|
| 홈 로그인 전 | `FO-MAI-A010000` | page · Native | page · webview(비회원) |
| 회원가입 혜택 | `FO-MAI-A010100` | page · webview | Layer · webview(비회원) |
| 개인화 서비스 안내 | `FO-MAI-A010200` | page · webview | Layer · webview(비회원) |
| 홈 로그인 후 | `FO-MAI-A020000` | page · Native | page · webview(회원) |
| 제휴카드 미등록 | `FO-MAI-A020101` | page · Native | content · webview(회원) |
| 제휴카드 등록 | `FO-MAI-A020102` | Layer · Native | content · webview(회원) |
| 여정 서비스 안내 | `FO-MAI-A020201` | Layer · Native | Layer · webview(회원) |
| 여정 미등록 | `FO-MAI-A020202` | page · Native | content · webview(회원) |
| 여정 등록 완료 | `FO-MAI-A020203` | content · Native | content · webview(회원) |
| 내 월렛 | `FO-MAI-A020300` | content · Native | Layer · webview(회원) |
| 개인화 추천 | `FO-MAI-A020401` | Layer · Native | page · webview(회원) |
| 테마 추천 | `FO-MAI-A020402` | content · webview | page · webview(공통) |
| 검색(바로 찾기) | `FO-CMM-A020000` | page · webview | `FO-CMM-B020000` |
| 공항위치 감지 안내 | 코드 없음 | 메인 행에 없음 | Layer · webview(회원) |
| 푸시 알람 | 코드 없음 | 확인되지 않음 | 확인되지 않음 |

목적지 이름은 기재되어 있으나 일부 화면 ID는 비어 있다고 보고되어 있다. 이름과 시트+코드의 대응을 확인한다(RC-02-009).

## 4. 답에 따라 달라질 작업 범위

| 확인 대상 | 함께 확인할 내용 | 웹·앱의 예상 영향 | 근거 |
|---|---|---|---|
| 플랫폼별 홈 구성 | 각 Figma의 APP·WEB 대응, 앱 내부 Native/WebView 연결 | 화면 이동·헤더·GNB 연결과 검증 범위 | RC-02-001 |
| 개인화 영역 상태 | 카드·여정 조합별 노출·버튼 동작과 기존 정의 위치 | 영역 표시·상태 갱신. 조합 수를 별도 화면·분기 수로 단정하지 않음 | RC-02-002 |
| 여정 안내·입력 연결 | 안내와 입력의 역할, 목적지·완료 후 표시 및 데이터 전달 | CTA 연결·완료 후 상태 반영 | RC-02-003 |
| 팝업 관계 | 동시 조건·재노출·도착 확인과 위치 허용 요청의 순서 | 노출 처리와 앱 권한 연동·검증 | RC-02-004, RC-02-005 |
| 개인화 동의 | 기획: 대상·거절 시 표시. Backend·앱: 계정·기기 범위 및 상태 전달 | 초기 표시·로그인 후 상태·권한 연결 | RC-02-006 |
| 전시·카테고리 | 기획: 관리 범위·항목 수·정렬·NEW 기준. Backend: 데이터 제공·계산·전달 계약 | 영역별 표시·연동·검증 | RC-02-007, RC-02-008 |
| 목적지 코드·번호 대응 | 기재된 목적지 이름과 시트+코드, 상태별 설명 대응 | 정확한 이동과 관련 검증 | RC-02-009 |
| 카드·이용권 | 기획: 한도·타입별 필드·버튼·취소 동작. Backend: 필드·대표카드 상태 전달 | 카드 영역·바텀시트 표시·동작 | RC-02-010 |
| 푸시 | 기획: 대상·시점·빈도·목적지. 앱·Backend: 발송·권한·실행 상태별 진입 계약 | 발송 연동과 실행 중·종료 상태의 진입 검증 | RC-02-011 |
| PC·태블릿 | 작성 중·검토 보류. 설명 보완 후 Figma·WEB IA 대응 재확인 | 현재는 상세 영향 판단 보류 | RC-02-012 |

이 표는 협의할 내용과 예상 영향이다. 팝업 수, 저장소, 계산 주체, 데이터 구조, 공통화 또는 선행 구현 방식을 결정하지 않는다.

## 5. 검증 관점

- **상태 조합:** 확인된 상태별 표시·CTA를 검증하고, 미확인 조합은 기획 확인 후 기대 결과를 추가한다.
- **팝업 상호작용:** 개별 트리거와 재노출 규칙을 구분한다. 동시 조건의 기대 결과는 답변 후 정하며, 한 개만 노출한다고 가정하지 않는다.
- **화면 연결:** 목적지 이름과 IA 시트+코드의 대응을 확인한다. 임의 목적지로 임시 연결하지 않는다.
- **데이터 경계:** BO 관리라는 기존 정의와 화면의 개수·NEW 규칙을 인정하고, 합의된 데이터·상태 전달을 기준으로 검증한다.
- **플랫폼·연동:** 앱 Native·앱 내부 WebView·반응형 웹을 구분한다. 기획 확인과 Backend·앱 계약 협의의 답을 각 과업에 적용한다.
- **PC·태블릿:** RC-02-012는 설명 보완 전까지 보류하며, 빈 설명으로 검증 항목을 늘리지 않는다.

## 6. 변경/재작업 가능성

아래는 실제 변경이나 재작업이 발생했다는 기록이 아니다. 확인 결과가 기존 구현·합의와 달라질 경우의 예상 영향이다. 실제 구현 상태는 미확인이다.

| 변경될 수 있는 기준 | 예상 영향 | 근거 |
|---|---|---|
| 플랫폼별 대응·앱 내부 배치 | 해당 과업의 화면 조립·공통 영역 연결 | RC-02-001 |
| 카드·여정 상태별 동작 | 표시·상태 갱신과 검증 범위 | RC-02-002 |
| 여정 안내·입력 역할 및 목적지 | CTA와 완료 후 표시 연결 | RC-02-003, RC-02-009 |
| 팝업 순서·동의 단계 | 진입·재노출·권한 연동 | RC-02-004~006 |
| 전시·카테고리 정책 및 데이터 계약 | 표시·정렬·NEW 처리와 연동 | RC-02-007, RC-02-008 |
| 카드·이용권 한도·필드·버튼 조건 | 카드 영역·바텀시트 표시 및 동작 | RC-02-010 |
| 푸시 대상·발송·진입 계약 | 발송 연동과 앱 진입 처리 | RC-02-011 |

RC-02-012는 검토 보류로 두며, 기획 보완 후 범위와 영향을 다시 기록한다. A의 질문 해소와 실제 개발·통합 완료는 별도로 관리한다.
