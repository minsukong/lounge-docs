## 1. 목적과 읽는 방법

현재 기획만 전달받은 작업자가 추가 질문 없이 동일한 결과를 만들 수 있는지 확인하기 위한 기록이다. 기획자 평가나 책임 판단을 목적으로 하지 않는다. 작업자가 결정해야 할 부분, 확인 요청, 작업 영향과 변경 가능성을 남겨 이후 답변·정책 확정·작업 변경을 추적한다.

**이 문서의 8개 항목은 확정 이슈가 아닌 이전 논의 기반 Review Candidate다.** 이전 대화에서는 검토용 복제본의 로그인 화면과 설명을 읽고 후보를 도출했다. 실제 기획 원본은 이후 접근 가능함이 확인되었지만, 이번 문서 작성 시 Figma MCP 조회 한도에 도달하여 각 후보를 원본과 다시 대조하지 못했다. 따라서 아래의 ‘이전 관찰’은 현재 원본에서 직접 재확인한 사실로 취급하지 않는다.

이전 검토 위치:

- [복제본 로그인 화면 / 7984:5682](https://www.figma.com/design/H8jvaSH1hEZYgxoxZftE4d/?node-id=7984-5682)
- [복제본 로그인 설명 / 7984:7723](https://www.figma.com/design/H8jvaSH1hEZYgxoxZftE4d/?node-id=7984-7723)

두 링크는 이전 논의의 출처를 추적하기 위한 것으로, 현재 정책의 기준 원본을 대체하지 않는다. 현재 원본의 해당 화면·설명 노드 ID와 발췌는 재검증 후 연결한다. 다른 페이지나 별도 정책·API 문서에 정의가 있을 가능성도 확인해야 한다. ‘이전에 확인되지 않음’을 ‘프로젝트 전체에서 미정의’로 확대하지 않는다.

## 3. 검수 분류와 상태

| 분류 | 확인할 내용 |
|---|---|
| [정책] | 대상·조건·제한·우선순위가 정의되어 있는가 |
| [Flow] | 진입·성공·실패·취소·복귀와 다음 화면이 연결되어 있는가 |
| [화면/상태] | 상태별 노출·문구·입력·버튼 동작을 재현할 수 있는가 |
| [데이터/API] | 필요한 데이터, 요청·응답, 오류와 세션 처리를 합의했는가 |
| [Native/Web] | Flutter·WebView·BE 등 처리 주체와 전달 경계가 정의되어 있는가 |
| [변경] | 기준 변경, 적용 범위와 재작업 여부를 추적할 수 있는가 |

한 후보에 여러 분류를 붙일 수 있다. [변경]은 실제 변경이 확인되었을 때 이력에 적용한다. 아래의 재작업 가능성은 예상 영향이며, 이미 변경이나 재작업이 발생했다는 뜻이 아니다.

상태는 `후보 → 원본 대조 → 사용자 검토 → 확인 요청 → 답변 수신 → 반영 확인 → 종료`로 관리한다. 후보는 원본 대조 결과에 따라 유지·수정·기정의로 종료할 수 있다. 실제 요청을 보내기 전에는 ‘확인 요청 완료’로 표시하지 않는다.

- **확인되지 않은 부분:** iOS/AOS별 노출 매핑과 생체인증 지원·설정에 따른 조건. 반응형 웹에도 이 화면을 적용하는지는 별도 확인이 필요하다.
- **확인 요청 초안:** 환경별 로그인 수단 목록과 각 수단의 노출·비활성 조건을 확인해 주세요. 앱과 일반 웹의 적용 범위도 구분해 주세요.
- **작업 영향:** 조건부 렌더링과 화면 구성, 환경별 QA 기준을 확정하기 어렵다.
- **임시 가정:** 없음. 임의의 플랫폼별 수단 매핑을 정책으로 채택하지 않는다.
- **변경/재작업 가능성:** 조건 확정 후 버튼 배치·노출 로직·QA 항목이 달라질 수 있다.
- **대조할 근거:** 현재 원본 로그인 화면·설명, 환경별 로그인 정책.

### RC-03-002 · SNS 인증 처리 흐름

- **확인 요청 초안:** 제공자별 인증을 Flutter SDK, WebView 또는 외부 인증 페이지 중 어느 영역이 시작하고 처리하는지 확인해 주세요. 성공·실패·취소 시 복귀 흐름도 연결해 주세요.

### RC-03-005 · 일반 로그인 실패 상태

- **이전 관찰:** 이전 검토에서는 정상 입력 중심의 화면을 확인했으며, 실패 상태 정의가 충분히 확인되지 않았다고 보고되었다.

- **확인 요청 초안:** 로그인 오류·계정 상태 목록과 API 응답에 연결되는 화면 행동을 확인해 주세요. 공통 오류 정책이 있다면 해당 문서·화면을 연결해 주세요.
- **작업 영향:** API 오류 매핑과 상태별 UI·QA를 구현할 때 작업자가 별도 판단해야 할 수 있다.
- **임시 가정:** 없음. 특정 계정 상태나 실패 횟수 정책을 새로 만들지 않는다.
- **변경/재작업 가능성:** 오류 계약 확정 후 메시지·버튼·분기·테스트 범위를 수정할 수 있다.
- **대조할 근거:** 현재 원본 실패 화면, 01. 공통의 오류 정의, BE 인증 응답 명세.

### RC-03-006 · SNS 회원 식별·계정 연결

- **이전 관찰:** SNS 로그인 수단이 있지만 동일 이메일 기존 회원·기연결 계정·신규 회원 분기가 명확히 확인되지 않았다고 이전 대화에서 보고되었다.
- **확인되지 않은 부분:** 회원 식별 기준, 기존 계정 연결 여부와 절차, 신규 SNS 인증 후 회원가입 경로·필수 단계.
- **확인 요청 초안:** SNS 인증 결과를 기존 회원·신규 회원·기연결 계정으로 구분하는 기준과 각 다음 화면을 확인해 주세요. 동일 이메일 계정에 대한 연결 정책도 확인해 주세요.
- **작업 영향:** 로그인과 회원가입 경계, BE 판별 결과, 추가 입력·동의·연결 화면 필요 여부가 달라질 수 있다.
- **임시 가정:** 없음. 동일 이메일만으로 계정을 자동 연결하거나 신규 회원을 자동 가입시키지 않는다.
- **변경/재작업 가능성:** 정책에 따라 계정 연결·회원가입 화면과 API 연동을 추가하거나 수정할 수 있다.
- **대조할 근거:** 현재 원본 SNS·회원가입·계정 연결 설명, BE 회원 식별 정책.

### RC-03-007 · 로그인 성공 후 이동

- **이전 관찰:** 로그인 수행 이후의 목적지와 원래 요청 화면 복귀가 명확히 확인되지 않았다고 이전 대화에서 보고되었다.
- **확인되지 않은 부분:** 직접 진입·로그인 요구 화면·외부 링크 등 진입 경로별 성공 후 목적지, 신규 회원가입 완료 후 복귀, 뒤로가기 동작.

- **작업 영향:** 인증 전후 라우팅, 목적지 보존과 앱·웹 뒤로가기 테스트가 달라질 수 있다.
- **임시 가정:** 없음. 로그인 후 항상 메인으로 이동한다고 확정하지 않는다.
- **변경/재작업 가능성:** 이동 정책 확정 후 라우팅과 기능별 인증 진입 연동을 수정할 수 있다.
- **대조할 근거:** 현재 원본 로그인 완료 설명, 로그인 진입 화면들의 이동 정의.

### RC-03-008 · 인증 결과·세션 전달

- **이전 관찰:** AOS/IOS 표기는 있었지만 Flutter ↔ WebView 간 인증 결과·토큰 전달 책임이 확인되지 않았다고 이전 대화에서 보고되었다.

- **작업 영향:** 로그인 버튼·화면과 별개로 앱·웹 인증 상태, 보호 화면 접근과 통합 테스트를 확정하기 어렵다.
- **임시 가정:** 없음. 토큰 저장 위치나 전달 방식은 합의된 계약 없이 결정하지 않는다.
- **변경/재작업 가능성:** 계약 확정 후 브리지·세션·API 인증 처리와 로그아웃 연동을 수정할 수 있다.

## 5. 작업자 보호를 위한 기록 양식

후보 검토와 실제 확인 요청·결정을 구분하여 아래 항목을 채운다. 답변자를 지정하거나 요청을 보낸 사실은 현재 없다.

|---|---|
| 후보 ID / 분류 | 위 ID를 유지하고 관련 분류를 기록 |

| 정의 상태 | 기정의 / 조건 모호 / 상충 / 검토 범위 내 미확인 / 명시적 미정 |
| 확인 요청 | 질문 내용·요청 일시·채널·대상. 발송 전에는 ‘미발송’ |
| 작업 영향 | 영향을 받는 화면·로직·담당 영역·테스트, 진행 가능한 범위 |
| 임시 가정 | 없음 또는 제안 내용·승인자·승인일·적용 범위·재검토 조건 |
| 답변·결정 | 답변 원문 또는 요약, 답변자·결정자·일시·근거 링크 |
| 변경·재작업 | 변경 전후, 적용일, 영향을 받는 작업. 발생 확인과 예상 가능성을 구분 |
| 반영·종료 | 기획/설계/구현 반영 위치와 확인일, 종료 근거 |
