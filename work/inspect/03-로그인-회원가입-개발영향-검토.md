## 1. 작업 관점에서의 핵심 문제

로그인은 웹 화면뿐 아니라 앱의 인증 실행, 인증 결과 전달, BE의 회원 판별과 세션 처리, 인증 후 화면 복귀까지 연결되는 기능이다. 화면에 로그인 수단이 표시되어 있어도, 환경별 조건과 영역별 처리 계약이 확인되지 않으면 웹 프런트엔드와 앱 개발자가 서로 다른 전제로 구현할 수 있다.

그 결과 담당 범위를 다시 나누거나, 각자 구현한 기능이 통합 단계에서 연결되지 않거나, 나중에 확정된 정책에 맞춰 화면·앱·API 연동을 함께 수정해야 할 가능성이 있다. 현재 확인 후보 중에서는 **SNS 인증 흐름(RC-03-002), 회원 식별·계정 연결(RC-03-006), 결과·세션 전달(RC-03-008)**이 여러 담당의 구현 전제를 함께 결정하므로 우선 협의 대상으로 제안한다.

이 문서는 근거 문서에 기록된 후보를 개발 영향으로 해석한 것이다. 현재 원본 재검증과 별도 기술 명세 확인은 수행하지 않았다. 아래 영향은 **후보의 불확실성이 실제로 남아 있는 경우의 예상 결과**이며, 확정된 기획 누락·개발 장애·일정 지연·재작업 실적이 아니다.

## 2. 항목별 웹·앱 개발 영향

| 근거 ID / 항목 | 웹 프런트엔드에 미치는 영향 | Flutter 앱 개발에 미치는 영향 | 공동으로 확인할 내용 |
|---|---|---|---|
| RC-03-001 · 로그인 수단 노출 | 앱 내 웹과 일반 웹의 노출 분기, 버튼 구성·상태를 확정하기 어려움 | OS·기기 지원·설정 상태를 웹에 알려야 하는지, 어떤 정보를 제공할지 확인 필요 | 환경별 수단·노출 조건 및 조건 판별 주체 |
| RC-03-002 · SNS 인증 흐름 | 버튼이 웹 인증을 시작하는지 앱을 호출하는지, 복귀·취소 처리 방식이 달라짐 | 앱이 인증 실행을 맡는 경우 제공자별 실행·외부 이동·복귀 처리가 필요하며 그 범위를 확정하기 어려움 | 제공자별 실행 주체·성공/실패/취소 흐름 |
| RC-03-003 · 생체인증 | 사용 가능 상태, 등록 안내·대체 로그인·실패 화면 분기를 확정하기 어려움 | 지원·등록·설정 상태 판별, 인증 실행과 결과 처리 범위를 확인해야 함 | 등록 전제·예외 정책 및 생체인증 후 서비스 로그인 연결 |
| RC-03-004 · 아이디 저장 | 입력 초기값, 체크 해제·로그아웃 시 값 처리와 저장 범위를 확정하기 어려움 | 앱 저장이 필요한 설계인지, WebView 값의 수명과 앱 생명주기를 연결해야 하는지 확인 필요 | 저장 책임·유지/삭제 조건·일반 웹과의 차이 |
| RC-03-005 · 로그인 실패 | API 오류별 문구·표시 위치·재시도·다음 화면 매핑을 확정하기 어려움 | 앱이 전달하는 오류와 웹이 표시하는 오류의 구분, 진행 중 상태 해제·취소 전달을 확인해야 함 | 실제 오류 목록·영역별 결과 분류·표시 책임 |
| RC-03-006 · 회원 식별·계정 연결 | 기존/신규 회원 분기에 따라 가입·연결·추가 입력 화면과 API 연동 범위가 달라짐 | SNS 인증 성공을 서비스 로그인 완료로 처리할 수 있는지, 웹의 추가 절차를 기다려야 하는지 확인 필요 | BE 판별 기준·결과 형식·후속 화면·최종 완료 시점 |
| RC-03-007 · 성공 후 이동 | 로그인 전 목적지 보존, 가입 이후 복귀와 웹 뒤로가기 정책을 확정하기 어려움 | 앱 화면·외부 링크에서 진입한 목적지와 웹 경로를 어떻게 연결할지 확인 필요 | 진입별 목적지·복귀·뒤로가기 규칙 |
| RC-03-008 · 결과·세션 전달 | 앱 인증 결과를 웹 상태·API 인증에 반영하는 방식과 세션 종료 처리를 확정하기 어려움 | 인증 결과 전달, 앱 로그인 상태와 웹 세션을 맞추는 책임을 확정하기 어려움 | 결과 전달 계약·세션 생성/만료/갱신·로그아웃 책임 |

위 표는 특정 SDK, 저장소, 토큰 전달 방식이나 구현 담당을 확정하지 않는다. 앱 관련 확인이 필요한 항목도 최종 설계에 따라 앱 작업이 없거나 범위가 달라질 수 있다.

## 3. 담당 간 구현 전제가 달라질 수 있는 사례

아래는 실제 발생 보고가 아닌, 협의가 필요한 이유를 설명하는 가상 사례다.

| 전제가 갈리는 지점 | 서로 다른 구현 전제의 예 | 통합 시 발생할 수 있는 결과 | 먼저 합의할 내용 |
|---|---|---|---|
| SNS 실행 주체 | 웹은 앱 인증 호출을 준비하고, 앱은 웹 인증 화면을 열어준다고 생각함 | 인증을 실제로 실행하는 처리가 빠지거나 중복됨 | 제공자별 인증 시작·처리·복귀 담당 |
| 로그인 완료 시점 | 앱은 SNS 인증 성공을 완료로 보고, 웹은 회원 판별·가입을 더 진행함 | 앱과 웹의 로그인 상태가 서로 다르게 표시될 수 있음 | 서비스 로그인 완료 조건과 최종 결과 전달 |
| 인증 결과·세션 | 앱은 결과만 전달하면 끝이라고 보고, 웹은 앱이 웹 세션까지 준비한다고 생각함 | 인증 성공 후에도 웹 API가 미인증으로 응답할 수 있음 | 세션 생성 주체·결과 형식·상태 반영 순서 |
| 성공 후 복귀 | 웹은 메인으로 이동하고, 앱은 원래 진입 화면 복귀를 기대함 | 인증은 성공해도 사용자가 요청한 흐름을 이어가지 못함 | 진입 경로별 목적지와 이동 담당 |
| 실패·취소 처리 | 앱과 웹이 모두 안내하거나 서로 상대 영역이 처리한다고 생각함 | 안내 중복·누락 또는 진행 중 화면 잔류 가능 | 결과별 표시·진행 상태 종료 책임 |

기획은 사용자에게 보이는 조건·행동을 확정하고, 개발 담당은 그 행동을 구현하는 기술 계약을 합의해야 한다. 화면 기획에 기술 세부사항이 없다는 이유만으로 기획 누락을 단정하지 않는다. 별도 명세나 협의 이력이 있으면 해당 근거를 연결한다.

## 4. 작업 진행과 완료 판단을 나누어 볼 부분

실제 코드·API·앱 준비 상태를 확인하지 않았으므로 아래는 작업 분리 제안이다. 전체 개발 중단을 의미하지 않는다.

| 작업 단계 | 진행할 수 있는 준비 작업 | 완료를 확정하려면 필요한 확인 |
|---|---|---|
| 화면 구성 | 이미 확인된 레이아웃·입력·공통 컴포넌트 작성 | 환경별 노출·상태·문구와 대상 화면의 최신 기준 |
| 웹·앱 연동 준비 | 합의가 필요한 데이터·이벤트 목록 정리, 인터페이스 초안 작성 | 실행 주체·결과 형식·호출/복귀 계약 |
| 분기 개발 | 분리 가능한 화면 구성, 모의 응답으로 동작 확인 | 회원 판별·예외·복귀 정책과 실제 응답 |
| 인증 통합 | 웹·앱·BE가 함께 실행할 시나리오와 준비 조건 정리 | 실제 인증 실행·세션 반영·실패/취소 연결 |
| QA·완료 확인 | 정상/예외/환경별 검증 항목의 초안 작성 | 합의된 기대 결과와 실제 환경의 통합 검증 |

모의 응답이나 임시 가정으로 구현한 결과는 해당 범위의 동작 확인이다. 실제 앱 인증 통합이나 정책 확정까지 완료했다고 기록하지 않는다. 임시 구현을 선택한다면 가정·적용 범위·승인자·변경 시 영향도 함께 기록한다.

## 5. 일정·공수·재작업에 미칠 수 있는 영향

- **공수 범위의 변동:** 인증 실행 방식과 계정 연결 정책에 따라 앱 연동, 추가 화면, API 분기가 늘거나 줄 수 있다. 현재 정보만으로 추가 일수를 산정하지 않는다.
- **통합 순서의 의존성:** 웹과 앱을 각각 구현해도 실행·결과·세션 계약이 맞아야 통합 완료를 확인할 수 있다. 각 담당의 구현 완료와 공동 통합 완료를 별도 기록할 필요가 있다.
- **QA 기준의 불확실성:** 기대 결과가 합의되지 않으면 같은 동작을 한쪽에서는 정상, 다른 쪽에서는 오류로 판단할 수 있다. 정책 확인과 코드 결함 수정을 구분해야 한다.
- **변경의 파급:** 공통 인증·복귀 규칙이 바뀌면 로그인 외의 인증 요구 화면에도 영향이 있을 수 있다. 어떤 기능에 전파되는지는 실제 연결 구조 확인 후 기록한다.
- **재작업 기록:** 기존 합의대로 구현했는지, 미확정 상태에서 어떤 가정으로 진행했는지에 따라 변경 원인을 구분한다. 현재 문서에서 재작업 발생이나 특정 담당의 책임을 확정하지 않는다.

## 6. 우선 협의할 산출물

새로운 대규모 문서 작성이 필수라는 뜻은 아니다. 기존 정의를 찾으면 링크하고, 없는 합의만 보완하는 방식으로 사용한다.

| 합의 대상 | 포함할 내용 | 관련 후보 | 함께 확인할 역할 |
|---|---|---|---|
| 로그인 환경·수단 표 | iOS/AOS/일반 웹 적용 범위, 노출·사용 조건 | 001, 003 | 기획·웹 FE·앱·QA |
| 제공자별 인증 흐름 | 시작·인증·복귀·취소·실패, 서비스 로그인 완료 시점 | 002, 003, 006 | 기획·웹 FE·앱·BE |
| 회원 판별·후속 화면 표 | 기존/신규/연결 계정의 판별 결과와 다음 행동 | 006, 007 | 기획·BE·웹 FE·앱 |
| 웹·앱·BE 인증 계약 | 호출과 결과 데이터, 세션 처리, 오류, 상태 반영 책임 | 002, 005, 008 | 웹 FE·앱·BE |
| 로그인 상태·복귀 기준 | 실패 안내, 저장값 처리, 목적지·뒤로가기, 종료 상태 | 004, 005, 007, 008 | 기획·웹 FE·앱·BE·QA |

‘함께 확인할 역할’은 협의 참여 제안이며 담당 배정이나 승인권 지정이 아니다. 사용자 정책과 기술 구현 방식을 나누어 적고, 결정 근거·결정일·적용 범위를 남긴다.
