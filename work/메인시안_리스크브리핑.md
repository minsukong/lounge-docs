## 🖼️ 1. 시안에 있는 것

- 📱 로그인 후 화면 **2장**: `#로그인후-미등록`, `#로그인후-제휴카드만 등록`
- 📇 eSIM 카드 변형 **2종**: 이용권 보유, 사용량 소진 임박
- ⬜ 나머지는 **빈 박스** 또는 한 줄 텍스트 자리

### 화면 구성

상단: 상태바 + 상단 내비게이션(88px) / 아래: 콘텐츠 영역(1757~1807px, **스크롤**)

#### ① 다이나믹 존 (화면 맨 위 카드 2장)

| | 🔵 미등록 | 🟢 제휴카드만 등록 |
|---|---|---|
| **My card** | "10명 중 9명, 이미 무료 이용권을 받았어요" + 등록 버튼 | 카드 목록(옆으로 넘김). 예시: "메리어트 본보이 더 프레스티지 카드™삼성카드", "공항 라운지: 통합 연 4회 제공 (본인 + 동반 1인)", **"+ 혜택 5건"**, "무료 혜택" 표시 바 |
| **내여정** | "여정 한번만 등록해두면, 다음부터는 공항에 맞는 라운지·이용권·혼잡도까지 **자동으로 떠요**" + 등록 버튼 | ⚠️ **미등록 카드와 동일. 등록 완료 상태가 없습니다** |

#### ② 상품 영역

- 🔵 미등록: 258px 빈 박스 → `title` 한 줄짜리 626px 박스 → 258px 빈 박스 — ❗**내용 없음**
- 🟢 등록:
  - "라운지 추천": SKYHUB Lounge, **인천공항 • Terminal 2**, 평점, 버튼
  - "더라운지에서 소개하는 이용권": eSIM 이용권(⚠️ **"런칭 기념 특별할인 최대 28%까지"**), 카테고리 3장: **"K공항 리무진"** · 공항 직통열차 사전예약 · 공항 다이닝

#### ③ eSIM 사용량 카드

📊 "0.5GB 남음/5GB" / "D-120만료" / **"15분 전 확인 기준"** + 갱신 버튼

#### ④ 주석으로만 있는 판정 규칙 ⚠️

> "1GB 이하인 경우 소진임박 판정, '소진임박' 배지 자체도 캐시 스냅샷 기준 판정, 이미 충전을 마친 유저라면 '갱신'을 누르는 순간 배지가 바로 사라짐"

🚨 **데이터 계약으로 정리된 곳은 없고, 이 메모 한 줄이 전부입니다.**

## 📊 2. 상태 목록: 있는 것과 없는 것

| 구분 | ✅ 시안에 있음 | ❌ 시안에 없음 |
|---|---|---|
| **제휴카드** | 미등록, 다수 등록 | 1장만 등록, 카드 해지, 혜택 소진 |
| **여정** | 미등록 | 🚨 **등록 완료, 여정 여러 개, 지난 날짜 여정** |
| **eSIM** | 미보유, 정상, 소진 임박 | 0GB, 만료, 충전 중, 여러 개 |
| **서버 데이터** | 정상만 | 🚨 **불러오는 중, 실패, 데이터 없음 — 전부 없음** |

> ⚖️ 조합하면 화면 **12가지**가 가능한데 시안은 **2개**. 나머지는 개발이 정합니다.
> 카드 여러 장이 함께 뜨면 위쪽 자리에 무엇을 넣을지도 정해져 있지 않습니다.

## ⚠️ 3. 문제 항목

| # | 시안의 값 | 문제 |
|---|---|---|
| 1 | "10명 중 9명" | 계산 값인지 승인 문구인지 **출처 미정** — 계산 값이면 통계 필요, 문구면 기간 필요 |
| 2 | "자동으로 떠요" 문구 | ① 여정 등록 완료 상태 없음 ② "인천공항 • Terminal 2"가 여정에 따라 바뀌는 값인지 예시 고정 값인지 **불분명** ③ "혼잡도"는 문구에만 있고 **표시할 자리 없음** |
| 3 | 카드 혜택 문장("연 4회 제공") | 카드사·연도마다 다름. 서버에서 주는 값인지 미정 — 미정이면 **카드 1종 기준으로 고치게 됨** |
| 4 | "+ 혜택 5건", "무료 혜택" 표시 바 | 누르면 가는 **화면 없음**. 표시 바가 남은 이용 횟수인지 설명 없음 |
| 5 | "최대 28%까지" | 할인 **기간·조건·종료 후 문구 미정** |
| 6 | eSIM 값 4종(사용량, 만료, 확인 시점, 임박 표시) | 전부 서버 값. "갱신" 동작과 "1GB 기준" 계산 위치(서버/화면) 미정 — 🚨 **협의 끝날 때까지 이 카드 개발 불가** |
| 7 | 빈 박스 3개 | 의도적 빈칸인지 미제작인지 **구분 불가** |

## ✅ 6. 담당별 할 일

### 🎨 디자인 (질문)
1. 빈 박스 3개: **의도적 빈칸인가, 미제작인가?**
2. 여정 등록 완료 상태 화면을 만들 것인가?
3. 카드 여러 장의 위쪽 자리 배분 우선순위는?
4. "10명 중 9명"의 출처는?
5. 실패·빈 화면 표현을 이번 시안에 넣는가?
6. "혼잡도"를 어디에 표시하는가, 아니면 문구에서 빼는가?

### 🖥️ 서버 (협의 대상)
1. eSIM: **값 목록, 1GB 기준 계산 위치(서버/화면), 갱신 버튼 값**
2. 카드별 혜택 정보(문장, 제공 횟수) 형식
3. 라운지 평점·혼잡도의 출처와 갱신 주기 — **혼잡도를 실제로 줄 수 있는가**
4. "10명 중 9명": 계산 값인가, 승인 문구인가
5. eSIM 할인의 기간·조건 값
6. 여정 데이터 → 추천 결과 변환 방식

### 💻 프론트엔드 (자체 준비)
1. 시안 표시 요소와 **기존 컴포넌트·토큰 대조 결과**
2. 2절에서 빠져 있는 **10개 상태의 화면 결정 규칙**
3. Safari 15에서 카드 목록 넘김·남은 양 바 동작 확인
4. 영역별 실패·불러오는 중 표기 방식 합의
5. 상태 조합 기준의 **스토리북 스토리 설계**
