# docs 작업 지침

이 파일은 `docs/` 아래의 문서와 문서용 HTML·자산에만 적용합니다. 루트 `AGENTS.md`를 반복하지 않고 문서 편집에 필요한 규칙만 보완합니다.

## 범위와 기준 확인

- 사용자가 지정한 문서와 필요한 주변 범위부터 확인합니다. 링크되어 있다는 이유만으로 다른 가이드, README, 템플릿과 소스를 연쇄적으로 읽지 않습니다.
- 문서 구조나 링크를 바꿀 때만 `docs/README.md`, 새 HTML 가이드를 만들 때만 `docs/templates/index.html`, 실제 구현 기준이 필요할 때만 관련 앱 소스나 상세 가이드 하나를 추가로 확인합니다.
- 상세 가이드는 `docs/guides/`, 공통 자산은 `docs/assets/`, AI 요약은 `docs/ai/`, 파일 단위 구현 예시는 `docs/common-source/`에서 관리합니다. 실제 애플리케이션 코드는 `apps/`에 둡니다.
- `docs/`는 제품 Build와 배포 대상이 아닙니다. 문서 검색, 링크, HTML과 JavaScript 검사는 문서 검증으로만 실행합니다.
- 저장소 구조, package, API와 계약을 설명할 때는 실제 소스와 승인된 계약을 확인합니다. 확인되지 않은 내용은 확정하지 않고 `TBD`로 구분합니다.
- 기존 기준과 다른 내용이 필요하면 문서에서 조용히 바꾸지 말고 충돌 지점과 변경 필요성을 먼저 알립니다.

## 문서 작성과 수정

- 사용자가 논의나 검토만 요청하면 파일을 수정하지 않습니다. 초안을 요청하면 대상 폴더의 `draft.md`, HTML 적용을 요청하면 대상 HTML을 수정합니다.
- 사용자가 기존 파일과 구체적인 요소를 지정한 작은 수정은 해당 요소와 인접 스타일만 확인해 바로 처리합니다. 문서 전체 재구성이나 관련 가이드 조사는 필요할 때만 수행합니다.
- 가이드는 백과사전식 배경보다 개발과 리뷰에 필요한 판단 기준을 짧게 제공합니다. 한 문단에는 한 주제를 두고 같은 설명을 반복하지 않습니다.
- 실제 사용처가 없는 폴더, 타입, Wrapper, Adapter와 추상화를 미리 만들도록 안내하지 않습니다.
- 확정된 기준과 미확정 내용을 같은 문장에 섞지 않습니다. 개별 미확정 항목은 결정할 내용을 포함한 `TBD`로 표시하되 상위 문맥이 명확하면 반복하지 않습니다.
- 코드나 문맥만으로 예시임을 알 수 있으면 `EXAMPLE` 같은 라벨을 반복하지 않습니다.
- 한국어 본문과 제목에는 자연스러운 표준 한국어를 사용합니다. 의도하지 않은 한자·중국어 문자, `U+FFFD`, 잘못 디코딩된 문자열과 보이지 않는 문자를 남기지 않습니다.
- Markdown과 HTML이 같은 내용을 표현하는 문서라면 사용자가 요청한 원본을 먼저 수정하고 필요한 동기화 범위만 갱신합니다. 검색 색인 같은 파생 파일은 원본 수정 후 공식 절차로 생성합니다.

## HTML 가이드

- 새 HTML 가이드는 `docs/templates/index.html`의 `header`, `main`, `section`, `hr`, `footer` 구조와 공통 자산 연결 방식을 따릅니다. 기존 HTML의 작은 수정은 현재 구조를 보존합니다.
- 주요 영역 제목은 번호가 포함된 `h2`를 사용합니다. `common.js`가 `h2`를 기준으로 메뉴를 만들므로 별도 목차를 중복 생성하지 않습니다.
- Header에는 문서 종류·제목·설명, Footer에는 문서명만 둡니다. 수기 문서에 버전, 날짜, `Draft` 같은 상태 정보를 추가하지 않습니다.
- 내부 문서는 목적이 드러나는 링크 텍스트와 상대 경로를 사용합니다.
- 코드 예시는 `<pre class="hljs"><code data-language="...">` 구조를 사용합니다. `text`가 아닌 코드는 기존 방식에 맞는 `hljs-*` 토큰을 사용하고 표시되는 문자·공백·줄바꿈을 바꾸지 않습니다.
- 코드 안의 `<`, `>`와 `&`는 HTML Entity로 처리하며 구문 강조용 `span`만 실제 태그로 둡니다.
- 개별 미확정 항목은 `<code class="badge-tbd">TBD</code>`를 사용합니다. `blockquote`는 핵심 원칙, 경고, 문서 우선순위와 실제 인용에만 사용합니다.
- 단순 목록으로 충분하면 표를 만들지 않습니다. 표에는 Header와 `scope`를 제공합니다.
- 다이어그램은 관계나 흐름을 더 명확하게 만들 때만 사용합니다. Mermaid에는 `accTitle`, `accDescr`과 `figcaption`을 제공합니다.
- 문서 전용 스타일과 동작은 기존 공통 자산을 우선하되, 한 문서에만 필요한 표현을 근거 없이 공통 자산에 추가하지 않습니다.

## 공통 자산

- `docs/assets/style/presentation-theme.css`와 `docs/assets/js/common.js` 변경은 모든 가이드에 영향을 주는 공통 변경으로 취급합니다.
- 공통 자산을 수정하면 기존 메뉴, 코드 접기, 반응형, 인쇄와 접근성 동작을 유지하고 대표 문서에서 회귀를 확인합니다.
- JavaScript로 생성하는 UI에는 키보드 사용, Focus 상태와 필요한 ARIA 속성을 함께 제공합니다.

## 검증

- 변경 범위에 맞춰 HTML 구조, 닫는 태그, 내부 링크와 CSS·JavaScript 경로를 확인합니다. 관련 없는 전체 문서 검사를 관성적으로 실행하지 않습니다.
- 코드 블록을 바꿨다면 Escape, `pre.hljs`, `hljs-*` 토큰과 표시 코드 보존 여부를 확인합니다.
- Header와 Footer의 문서명, 불필요한 버전·날짜·상태 표시, `TBD`, `blockquote`, 표와 다이어그램 규칙을 변경 범위 안에서 확인합니다.
- 시각 요소를 수정했다면 가능한 경우 Desktop과 Mobile 너비에서 확인합니다. 수행하지 못하면 그 제한을 보고합니다.
- `common.js`를 수정하면 JavaScript 문법을 검사하고, 공통 자산을 수정하면 대표 기존 가이드에 미치는 영향도 확인합니다.
- 수정한 한국어 범위에서 의도하지 않은 한자·중국어 Unicode 범위와 `U+FFFD`를 확인합니다. 기계적으로 일괄 치환하지 않습니다.
- 기존 사용자 변경과 관계없는 파일 또는 서식을 수정하지 않습니다.

## 변경 기록

- `docs/CHANGELOG.md`는 가이드 생성·삭제·이동, 여러 섹션의 구조 개편, 문서 흐름·정책·공통 자산에 영향을 주는 대규모 변경에만 갱신합니다.
- 문구·오타·단일 섹션·스타일·이미지와 제한된 유지보수는 기록하지 않습니다. 불명확하면 변경 기록을 읽거나 수정하지 않습니다.
- 교육 과정과 초안은 사용자가 기록을 요청한 경우에만 추가합니다.
- 기록할 때는 최신 날짜 아래에 목적, 주요 변경, 미확정 항목과 검증 결과를 하나의 항목으로 작성합니다.

## 리뷰 요청

- 구현 요청이 없는 리뷰는 읽기 전용으로 수행합니다. 사용자가 지정한 파일과 폴더만 검토하고 근거가 확인된 내용만 보고합니다.
- 현재 파일만으로 판단할 수 없으면 추측하지 않고 그 한계를 표시합니다. 추가 파일이 반드시 필요할 때만 이유와 최소 범위를 알립니다.
- `전반적으로`, `충분한지` 또는 `부족한 부분`만으로 범위를 전체 프로젝트로 확장하지 않습니다.
- 사용자가 명시하지 않은 Backend, 인증, 인프라, 배포, 새 기능과 아키텍처 개편으로 리뷰를 넓히지 않습니다.
