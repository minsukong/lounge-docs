아키텍처 다이어그램 가이드

이 폴더는 더라운지 시스템 3.0의 아키텍처 다이어그램을 관리합니다. 현재는 설계 단계의 예상 시나리오(Mermaid)를 유지하고, 실제 코드 구현 이후에는 Archify를 통해 정적 구조를 검증 가능한 인터랙티브 HTML 다이어그램으로 전환합니다. Build와 API 실행 결과는 별도 실행 결과를 연결한 경우에만 표시합니다.

1. 폴더 목적

이 폴더는 프로젝트의 시스템 구조를 시각화하고 추적하기 위해 사용합니다. 팀 내 개발자, 운영자, 신규 인력이 저장소를 한눈에 파악할 수 있게 하는 공통 참조 자료입니다.

2. Archify란

Archify는 AI Agent Skill입니다. 저장소의 실제 코드를 분석하여 검증 가능한 인터랙티브 HTML 다이어그램을 생성합니다.

핵심 특성

항목 설명
출력 셀프컨테이널 HTML 파일 1개 (서버/호스팅 불필요, 브라우저로 열면 됨)
정적 구조 검증 타입드 JSON → 스키마 검증 → 레이아웃/라벨/라우트 충돌 체크
실행 결과 검증 Archify가 임의로 실행하지 않음. 프로젝트 또는 CI가 만든 Build, Test, API 검증 결과를 연결하는 방식은 향후 검토
코드 근거 노드에 실제 소스 파일 경로 링크 (클릭 시 해당 파일로 이동)
관계 강조 노드 선택 시 선택 노드, 직접 연결된 노드와 그 사이 화살표를 함께 강조하고 나머지 관계는 흐리게 표시
테마 Dark/Light 자동 전환
내보내기 PNG / JPEG / WebP / SVG / WebM
Delta 두 시점의 다이어그램을 비교하여 추가/삭제/이동 표시
설치 npx skills add tt-a1i/archify -g (AI IDE 사용자만 필요)
프로젝트 내 설치 없음. 제품 package.json과 Build Pipeline에 포함하지 않고, 실행 결과 연동 시에도 기존 Script의 결과만 읽는 방식을 우선

목적 "이렇게 될 계획" 문서화 "실제로 이렇게 구현됐다" 검증

3. Archify 적용 시점과 방법

적용 시점

시점 용도
Phase 1 완료 (UI 컴포넌트 + API adapter 구현 후) 초기 아키텍처 맵 생성 + 실제 코드 검증
Feature 추가/변경 시 Delta 다이어그램 (무엇이 바뀌었는지 확인)

5. 빌드 시나리오 다이어그램

아래는 apps/app-webview의 빌드 파이프라인 가상 시나리오입니다. 실제 package.json이 생성되기 전, 알려진 기술 스택(Next.js 16 · React 19 · Tailwind CSS 4 · Storybook) 기반으로 Source → Compile → Output → Verify → Result → Deploy 흐름을 시각화한 것입니다.

레인 구성:

  • SOURCE — App Router, 컴포넌트, Tailwind 4, TypeScript, Storybook 설정
  • COMPILE — TypeScript·TSX 변환, Tailwind CSS 처리, Next.js Build와 React 렌더링
  • OUTPUT — .next/, 정적 자산, 렌더링 결과 후보, storybook-static/
  • VERIFY — typecheck, lint, test, Storybook Build, 제품 Build와 승인된 API 통합 테스트 후보. 실제 Script, API 테스트 환경과 차단 조건은 TBD
  • RESULT — 각 검사의 exit code, 요약 로그, 응답 상태와 실행 시각을 수집해 PASS, FAIL, SKIP, NOT RUN 상태로 연결하는 후보. 결과 형식과 연동 방식은 TBD
  • DEPLOY — 정적 호스팅과 Next.js 서버를 대안으로 비교하고, Flutter WebView가 승인된 HTTPS 주소를 로드하는 흐름. 배포 방식과 연계 범위는 TBD

노드를 선택하면 선택 노드, 직접 연결된 노드와 그 사이 화살표가 함께 강조됩니다. 같은 노드를 다시 선택하거나 배경을 선택하면 강조가 해제됩니다.

이 다이어그램은 패키지 설치 전의 가상 시나리오입니다. 실제 package.json, Next.js 설정, CI와 배포 방식이 정해진 뒤 확인된 흐름으로 갱신합니다. 정적 코드 연결과 실행 성공 여부는 구분하며, Build와 API의 PASS 또는 FAIL은 실제 명령과 승인된 테스트를 실행한 결과가 있을 때만 표시합니다.

6. 운영 기준

  • [TBD] 파일은 확정 전 문서입니다. Backend 확인 및 기획 승인을 거친 후 파일을 수정하고 [TBD] 프릭스를 제거합니다.
  • Archify HTML 산출물은 이 폴더에 commit합니다. Git 히스토리로 시점별 아키텍처를 추적합니다.
  • 빌드 제외: 이 폴더의 모든 파일은 next build 대상이 아닙니다.
  • 공유: HTML 파일은 셀프컨테이널이라 Slack/Confluence/이메일로 첨부하면 됩니다. 별도 호스팅 불필요.
  • Archify 설치: 결과물(HTML)을 보는 사람에게는 설치 불필요. AI로 다이어그램을 만드는 사람만 AI IDE + Skill 설치.
