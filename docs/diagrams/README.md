## Archify 활용

### 왜 쓰는가

| 구분 | Mermaid (현재) | Archify (향후) |
|------|---------------|----------------|
| 목적 | "이렇게 될 **계획**이야" 문서화 | "실제로 이렇게 **구현**됐다" 검증 |
| 근거 | 작성자의 지식/설계서 | **실제 코드 파일 분석** |
| 정적 구조 검증 | ❌ 없음 | ✅ 노드·연결이 코드에 실제로 존재하는지 타입드 검증 |
| 실행 결과 검증 | ❌ 없음 | ⏳ 별도 실행 결과 연동 시 Build·Test·API 상태 표시 가능 |
| 산출물 | Markdown 내 인라인 다이어그램 | 셀프컨테이널 HTML (브라우저에서 바로 열림) |
| 변경 추적 | 수동 | Architecture Delta (Before/After diff) |
| 사용 대상 | 개발/기획/리뷰 | 개발/운영/온보딩/외부 공유 |

**핵심 가치:** AI가 저장소를 읽어서 "이 컴포넌트가 실제로 존재하는가, 이 import가 실제로 있는가"를 검증한 뒤 다이어그램을 만들어 줍니다. 문서와 코드가 어긋나면 정적 구조 검증에서 차이를 확인할 수 있습니다.

### 정적 구조 검증과 실행 검증

Archify의 기본 역할은 실제 소스 파일, import와 의존 관계를 근거로 구현 구조를 확인하고 다이어그램으로 표현하는 것입니다. 코드 연결이 존재한다는 사실만으로 Build 명령이나 API 통신이 성공했다고 판단하지 않습니다.

실제 애플리케이션이 구성된 뒤에는 프로젝트 또는 CI가 다음 결과를 수집하고, 공통 결과 파일을 통해 Archify 노드와 연결에 상태를 표시하는 방식을 검토합니다.

| 검증 종류 | 수집 대상 | 표시 대상 | 조건 |
|------|------|------|------|
| Build | 실제 Script의 exit code, 실행 시간, 요약 로그 | Build 노드 | `package.json`에 Script가 존재할 때 |
| 품질 검사 | typecheck, lint, test, Storybook 정적 Build 결과 | 각 품질 검사 노드 | 프로젝트에 정의된 검사만 실행 |
| API | health check 또는 integration test의 응답·계약 검증 결과 | 검증한 API 노드 또는 연결 | 승인된 계약, 테스트 주소와 인증 조건이 있을 때 |

상태는 `PASS`, `FAIL`, `SKIP`, `NOT RUN`으로 구분합니다. Build 실패를 API 연결 실패로 추측하는 것처럼 근거가 없는 상태 전파는 하지 않습니다. CORS와 WebView 전용 동작은 실제 브라우저 또는 WebView 검증 결과가 있을 때만 표시합니다.

실행 기능을 Archify 내부에 크게 포함하지 않고, 기존 프로젝트 Script와 테스트 도구가 만든 결과를 얇은 어댑터로 읽는 방식을 우선합니다. 이 방식은 Archify의 목적을 코드 기반 아키텍처 시각화로 유지하면서도 필요한 경우 실제 검증 상태를 함께 보여 줍니다.

### 인터랙티브 표시 기준

클릭 가능한 Archify HTML 다이어그램은 노드를 선택하면 선택한 노드, 직접 연결된 노드와 그 사이의 화살표를 함께 강조합니다. 관계없는 노드와 연결은 흐리게 표시하고, 같은 노드를 다시 선택하거나 다이어그램 배경을 선택하면 강조를 해제합니다. 이 기준은 정적 Mermaid 문서가 아니라 인터랙티브 HTML 산출물에 적용합니다.

### 현재 상태

| 항목 | 상태 |
|------|------|
| `apps/app-webview/` | 초기화 전 (코드 없음) |
| 다이어그램 | **초기 계획용** — 예상 시나리오 기반, 실제 코드·실행 검증 불가 |
| Archify 적용 | ⏳ 코드 구현 후 (Phase 1~2 완료 시점) |

### 언제 적용하는가

| 시점 | Archify 용도 |
|------|-------------|
| Phase 1 완료 (UI 컴포넌트 + API adapter 구현 후) | 초기 아키텍처 맵 생성 + 검증 |
| Feature 추가/변경 시 | Delta 다이어그램 (무엇이 바뀌었는지) |
| 운영 이관 시 | 최종 아키텍처 HTML 산출물 전달 |
| 온보딩 시 | "저장소 아키텍처 맵 만들어줘" |

### 어떻게 쓰는가

```bash
# 설치 (AI IDE 사용자만, 한 번만)
npx skills add tt-a1i/archify -g
```

AI IDE (Cursor, Claude Code 등)에서:

```
"docs/diagrams/[TBD]_architecture-overview.md의 내용을 archify로
검증 가능한 아키텍처 다이어그램으로 만들어줘.
apps/app-webview 실제 코드 기준으로 확인하고,
코드에 없는 컴포넌트나 연결은 제외해줘."
```

**출력물:** 이 폴더에 `*.html` 파일로 저장. 별도 서버/호스팅 불필요, 브라우저로 열면 됩니다.

**제품 Build와 분리:** Archify는 프로젝트 내 패키지가 아니며 산출물은 정적 HTML 파일이라 `next build`에 포함되지 않습니다. 향후 실행 결과를 연동하더라도 프로젝트 또는 CI의 기존 Script를 외부에서 실행하고 결과만 읽는 방식을 우선합니다.
