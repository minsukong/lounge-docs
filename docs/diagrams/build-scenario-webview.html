현재 상태

설계 시나리오 · NOT RUN

현재 app-webview에는 package.json과 실제 구현 소스가 없습니다. 표시된 명령, 산출물과 API 검증은 구현 후 확인할 후보이며 현재 성공을 의미하지 않습니다.

정적 구조 검증

Page → Query → API Client → Backend

실제 소스가 생기면 파일, import와 의존 관계를 분석해 노드와 연결의 존재 여부를 확인할 수 있습니다. 이는 API 응답 성공이나 빌드 실행 성공을 보장하지 않습니다.

빌드 및 품질 실행 검증 (TBD)

typecheck · lint · test · build:storybook · build

실제 package.json에 정의된 script만 실행합니다. 별도 실행기가 종료 코드, 실행 시간과 요약 로그를 공통 결과로 저장하면 다이어그램의 대응 노드에 PASS, FAIL, SKIP 상태를 연결할 수 있습니다. Safari 15와 WKWebView 호환성은 별도의 브라우저 실행 검증으로 확인합니다.

API 실행 검증 (TBD)

health check · integration test

승인된 API 계약, 테스트 주소와 인증 조건이 있을 때만 실제 요청 결과를 수집합니다. 응답 코드, 타임아웃과 계약 검증 결과를 API 노드 또는 해당 연결에 표시하며 운영 API를 임의로 호출하지 않습니다.

판정 원칙

구조 존재 ≠ 실행 성공

빌드 실패는 빌드 노드에, 특정 API 통합 테스트 실패는 검증한 API 노드나 연결에 표시합니다. 근거가 없는 실패 전파나 원인 추정은 하지 않고 원문 로그와 실행 환경을 함께 남깁니다.
