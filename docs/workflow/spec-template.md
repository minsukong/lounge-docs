# 기능 명세 템플릿

여러 세션·카드에 걸치는 기능에서 사용합니다. 작은 변경은 작업 카드로 충분합니다. 기존 대화와 합의된 근거를 기록하며, 새로운 업무 정책을 이 양식에서 임의로 결정하지 않습니다.

# [명세 ID]: [기능]

## 문제·사용자 목표
누가 어떤 상황에서 무엇을 완료하려는지 적습니다.

## 범위·플랫폼
App-WebView / Responsive-Web / Native의 책임과 이번 제외 범위를 구분합니다.

## 근거
IA 파일·원본 행·화면 ID, 승인 기획·계약·결정 링크를 적습니다. IA 후보와 합의된 내용을 구분합니다.

## 사용자 흐름·상태
진입 → 입력·선택 → 성공 결과를 적고, 해당하는 실패·취소·뒤로가기·재진입·빈 상태·로딩·오프라인을 설명합니다.

## 업무 용어·정책
기능에 필요한 용어와 합의된 정책만 적습니다. 미정 부분은 [결정 기록](decisions.md)의 결정 ID에 연결합니다. 주문·결제·이용권·쿠폰의 관계를 서비스 소개에서 추측하지 않습니다.

## 계약·플랫폼 경계
API·인증·데이터·Bridge 계약의 상태와 책임자, 버전·근거를 적습니다. 이번 기능에 필요한 [계약 검토](contract-review.md) 결과를 연결합니다.

## 구현 판단
관련 모듈·재사용 방향·상태 책임·기존 패턴과 바뀌는 경계를 적습니다. 파일·라인의 상세 구현 계획은 실제 작업 카드에서 최신 소스 확인 후 작성합니다.

## 완료 조건·검증
사용자 결과로 검수 조건을 적고 행동·폼·분기·연동 중 검증할 경계, Story와 실기기 대상, 미실행 검증의 영향을 설명합니다.

## 작업 분해
[작업 카드 양식](task-card.md)으로 작성한 실제 카드 링크, 각 카드의 결과, 실제 Blocked by와 해소 증거를 연결합니다. Ready는 카드별로 판단합니다.

## 미정·제외·재개
결정 대기·적용하지 않는 부분·현재 다음 행동을 기록합니다. 이 명세가 작성됐다는 이유로 전체 기능을 Ready로 표시하지 않습니다.
