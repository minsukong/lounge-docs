실제 작업은 [작업 카드 양식](task-card.md)으로 만든 카드에서 관리합니다. [결정 기록](decisions.md)·[계약 검토](contract-review.md)·[IA 기준](ia-baseline.md)의 근거를 카드에 연결하고, 여기에는 상태와 다음 행동을 요약합니다. [전체 연결 안내](index.md)를 참고합니다.

> 후보 목록의 기존 표시: `[ ]` 대기 / `[~]` 진행중 / `[x]` 완료. 아래 표의 `[ ]`는 Ready 판정이 아닙니다.

## 화면 수와 개발량의 구분

기존 “MO 134, 웹 약 134, 확정분 약 270” 표현은 검증된 개발량이 아니므로 확정 수치로 사용하지 않습니다. IA의 고유 ID 수·화면/레이어/링크 수·작업 카드 수는 서로 다릅니다. 최신 파생 ID 수는 [자동 대조 결과](ia-audit.md)를 봅니다.

- MO·WEB: 주 과업의 후보 구조. 기능·정책·화면 공유·반응형 차이는 카드별 확인.
- APP: Native 경계 참고. FO ID와 Native/WebView 혼재.
- 판매채널: 단순 포맷 또는 작업량 적음으로 확정하지 않음. 추가 정보 필요.
- PO·OO: 별도 범위 후보. 담당·검수 책임 미정.
- 개발량·일정: 실제 카드의 범위·의존성·담당·검증 조건이 정해진 후 산정.
