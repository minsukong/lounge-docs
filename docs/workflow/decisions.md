# 결정·질문 기록

결정은 TBD → Proposed → Confirmed / Rejected / Superseded로 기록합니다. Proposed는 구현 승인으로 취급하지 않습니다. 질문이 여러 개면 기능의 착수를 막는 순서로 확인합니다.

실제 업무에서 확인할 질문은 출처·원본 근거를 함께 기록합니다. 관련 [계약 검토](contract-review.md)와 [작업 카드](task-card.md)에 결정 ID를 연결하고, 합의 결과는 영향받는 명세·카드에 반영합니다. [전체 연결 안내](index.md)를 참고합니다.

## Figma(기획서) 보완 코멘트 — 프론트·백엔드 공통 양식

프론트와 백엔드가 같은 항목으로 기획 누락·충돌과 결정할 내용을 전달하는 공통 코멘트 양식이다. 사람과 AI 모두 사용한다. 각 가이드에 양식을 포함해 다른 가이드 폴더 없이 사용할 수 있게 유지한다.

관련 화면·설명·기존 결정·코멘트에 답이 있는지 먼저 확인한다. 읽지 못한 범위는 미확인으로 남기며, 확인한 자료에서 찾지 못한 내용을 질문한다. 한 코멘트에는 함께 결정해야 할 한 가지 주제를 담고, 같은 질문이 있으면 기존 스레드에 이어서 남긴다.

```text
[기획 보완 요청] <기능> — <결정할 항목>
대상: <화면명·노드 링크>
현재 확인: <관련 화면·설명에서 확인한 내용>
확인 요청: <실제 상황과 결정할 질문>
기획서 반영 요청: <추가할 정책·조건·분기·상태 설명>
개발 영향: <영향받는 API·데이터·테스트, 진행·보류 범위>
협의 대상: <결정할 역할·담당자, 모르면 확인 필요>
```

항목명과 순서는 프론트·백엔드에서 동일하게 사용한다. ‘개발 영향’에는 담당 영역에 맞게 프론트의 화면 상태·입력 검증·이동 흐름, 백엔드의 API·데이터·트랜잭션과 관련 테스트, 진행·보류 범위를 적는다. 양식을 변경할 때는 양쪽 가이드도 같은 기준인지 확인한다.

‘기획서 반영 요청’에는 결정 후 어느 흐름·상태·설명에 무엇을 추가해야 하는지 쓴다. 실제 담당·기한은 확인된 경우에만 지정하고, 기술 제안·선택지는 확정 정책과 구분한다. 관련 DEC·작업 ID가 있으면 연결한다.

### 프론트 작성 예시

다음은 양식 사용 예시이며 실제 회원가입 정책이나 검토 결과가 아니다.

```text
[기획 보완 요청] 회원가입 — 인증 만료 후 재시도
대상: 회원가입 인증 화면 / <실제 화면·노드 링크>
현재 확인: 인증 진행 화면은 있지만, 검토한 화면·설명에서 인증 만료 후 동작을 찾지 못했습니다.
확인 요청: 인증이 만료되면 입력값을 유지한 채 다시 인증하나요? 재인증 성공 후에는 어느 단계로 이동하나요?
기획서 반영 요청: 만료 안내, 입력값 유지 범위, 재시도 동작과 성공 후 이동을 인증 흐름에 추가해 주세요.
개발 영향: 화면 상태·입력값 보존·API 오류 처리·이동 흐름·테스트에 영향을 줍니다. 해당 분기는 결정 후 구현하고, 기존 흐름 조사와 독립적인 UI 작업은 진행할 수 있습니다.
협의 대상: 기획 담당과 프론트·백엔드 협의 필요 / 실제 담당 확인 필요
```

### 사람과 AI의 작성·게시

- 사람: 대상 화면의 관련 위치에 코멘트 핀을 두고 공통 양식으로 작성한다. 긴 내부 설계 내용은 작업 기록으로 연결한다.
- AI 초안: 대상 화면·노드 링크와 검토 범위를 제공하고 lounge-grill과 공통 양식으로 작성하게 한다. 초안 작성 요청은 게시 요청과 구분한다.
- AI 게시: 사용자가 게시를 요청한 대상·범위에서 실제 코멘트 게시 도구와 계정 권한을 확인해 수행한다. MCP 연결이나 캔버스 편집 지원만으로 코멘트 게시가 가능하다고 가정하지 않는다. 게시 도구·권한이 없으면 초안과 필요한 설정을 안내한다.
- 게시 결과: 반환된 코멘트 ID·링크로 실제 게시를 확인한다. 초안·게시 실패를 게시 완료로 기록하지 않는다. 기존 코멘트를 임의로 삭제·해결 처리하지 않는다.

AI 초안 요청 예시:

```text
Figma(기획서): <대상 화면·노드 링크>
```

### 답변 이후 결정·작업 연결

기획 확인 → 코멘트 작성·게시 → 담당자 답변 → 결정 기록 → 작업 범위 갱신 순서로 연결한다. 질문 작성부터 초안·미게시 상태와 관련 DEC를 연결하고, 게시 후에는 대상 화면·코멘트 ID 또는 링크를 근거에 추가한다.

답변을 받으면 결정 권한이 있는 담당과 내용을 확인하고, 결정자·근거·적용 범위를 해당 DEC에 반영한다. 관련 카드의 진행·보류 범위와 재개 조건을 갱신하고 기획서 반영 여부도 확인한다. 미반영이면 그 상태를 남긴다. 코멘트 게시나 답변 수신만으로 Confirmed 또는 개발 완료로 처리하지 않는다.
