# 결정·질문 기록

결정은 TBD → Proposed → Confirmed / Rejected / Superseded로 기록합니다. Proposed는 구현 승인으로 취급하지 않습니다. 질문이 여러 개면 기능의 착수를 막는 순서로 확인합니다.

기획 리뷰에서 가져온 질문은 출처 RC·원본 근거를 함께 기록합니다. 관련 [계약 검토](contract-review.md)와 [작업 카드](task-card.md)에 결정 ID를 연결하고, 합의 결과는 영향받는 명세·카드에 반영합니다. [전체 연결 안내](index.md)를 참고합니다.

## 개별 결정 기록 양식

### DEC-번호: 제목
- 상태:
- 질문과 실제 선택지:
- 결정을 필요로 하는 카드:
- 책임자·협의 상대:
- 근거·대화·회의·계약 링크:
- 결정 내용과 적용 범위:
- 선택한 이유·대안:
- 변경 시 영향:
- 해소 증거·관련 카드 갱신:

역전 비용이 크고 대안 선택 이유를 남겨야 하는 결정만 별도 ADR로 승격합니다. ADR은 기술 결정 기록이지 승인되지 않은 업무 정책을 확정하는 수단이 아닙니다. 용어집은 실제 정의가 합의될 때 작성하며 결정 대기 목록으로 사용하지 않습니다.
