## API 검토

| 항목 | 확인할 내용 | 결과·질문 |

| 동작·입출력 | 승인된 요청·응답, 필수/선택/null, enum, 검증, 필드 의미 | |
| 목록·수치 | 페이지·정렬, 금액·시간·단위·시간대의 의미가 필요한 경우 | |

API 문서에 없는 endpoint·응답 스키마를 검토자가 만들어 확정하지 않습니다. API 합의가 있어도 운영 정책·Bridge 차단이 남으면 전체 연동 Ready가 아닙니다.

## Bridge 검토

| 항목 | 확인할 내용 | 결과·질문 |
| --- | --- | --- |
| 책임 | Web·Flutter 중 시작·실행·완료·사용자 오류 안내의 담당 | |
| 메시지 | 합의된 명령·payload·버전과 응답·이벤트의 의미 | |
| 수명 주기 | 준비 전 호출, 요청/응답 연결, timeout·취소·중복 callback | |
| 이동 | 아래 [이동·복귀 검토](#이동복귀-검토)의 해당 흐름과 처리 담당·결과 전달 계약 | |
| 권한 | 허용·거부·제한·설정 변경 후 복귀 중 적용 상태 | |
| 인증 | 세션 전달·갱신·로그아웃 책임과 민감정보 저장·로그 경계 | |
| 플랫폼 | Android/iOS 차이, 웹 브라우저에서 해당 기능의 동작 또는 제외 | |
| 검증 | 지원 기기·OS·앱 버전과 실제 재현 결과 | |

합의되지 않은 command 이름·전역 객체·token 전달 방식·fallback을 만들지 않습니다. Android/iOS 차이는 실제 계약과 기존 adapter에서 확인하며 화면에 플랫폼 객체를 직접 노출하지 않습니다.

## 이동·복귀 검토

화면 이동이 포함된 카드에서 필요한 항목만 작성합니다. WebView 중심 화면도 Native 기능·외부 앱·직접 진입의 이동 경계를 확인합니다. 카메라·QR 스캐너의 결과 반환은 Bridge 복귀이며, 링크로 앱의 특정 화면에 진입하는 딥링크와 구분합니다.

뒤로가기, 상위 화면 이동, 작업 완료·취소·닫기의 의미를 먼저 정합니다. `history.back()`·`router.back()`을 목적지 확인 없이 공통 처리로 사용하지 않습니다. 안전한 앱 내부 이전 화면과 해당 복귀가 이번 흐름에 맞는지 확인된 경우에만 이력을 사용하고, 이력이 없거나 외부·완료된 처리 화면으로 이어지면 합의된 내부 목적지를 사용합니다. `history.length`만으로 이전 목적지가 안전하다고 판단하지 않습니다. 목적지가 미정이면 임의로 홈·목록을 정하지 않고 관련 카드에 TBD로 남깁니다.

| 항목 | 확인할 내용 | 결과·질문 |
| --- | --- | --- |
| 앱 내부 이동·뒤로가기 | 진입 화면·경로, 뒤로가기와 상위 이동의 차이, 사용할 앱 내부 이전 화면과 그 확인 근거, 직접 진입·이력 없음·부적절한 이력에서의 대체 목적지 | |
| 상태 유지 | 목록 검색·필터·페이지·스크롤, 입력 중 값과 변경 사항, 유지·초기화할 상태와 사용자 전환 시 정리 범위 | |
| Native 기능 완료·취소 | 카메라·QR 스캐너·사진 선택의 결과·취소·권한 거부, 기존 WebView 유지와 결과 전달, Native 화면 닫기 담당, WebView 재생성 시 복구 방식. 결과·취소를 중복 전달하지 않도록 확인 | |
| 외부 앱·브라우저 복귀 | 외부 결제·인증·OS 설정에서 돌아왔을 때 기존 화면 재개 또는 복구 목적지, 실행 중·앱 종료 후 재시작의 차이, 취소·복귀 유실·결과 재확인. 앱 복귀만으로 업무 성공을 판정하지 않음 | |
| 딥링크·푸시 진입 | 지원할 진입 유형·허용 내부 목적지·파라미터, 로그인 전 목적지 보존, 앱·WebView 준비 전 이벤트 전달, 실행 중·종료 상태의 화면 구성, 중복 수신 처리. 푸시가 딥링크 형식을 사용할지는 별도 결정 | |
| 로그인·업무 완료 후 이동 | 합의된 완료·복귀 목적지와 이력 추가·대체 기준, 로그인·결제 입력 화면 재진입 시 처리, 로그아웃·계정 전환 후 권한 재검증과 상태 정리. 이력 대체만으로 재처리·접근을 차단했다고 판단하지 않음 | |
| 처리 담당과 루트 화면 | 화면 버튼·Android 시스템 뒤로가기·지원하는 제스처의 적용 규칙, 열린 팝업·Native 화면·웹 화면별 처리 우선순위, 한 입력을 Native와 Web이 동시에 처리하지 않는 계약, 앱 루트에서의 동작 | |
| 실제 검증 | 목록→상세→복귀, 직접 진입, 팝업 닫기, Native 완료·취소·권한 거부, 외부 앱 복귀, 로그인·로그아웃·완료 후 뒤로가기 중 이번 카드에 해당하는 흐름. 지원 기기·OS와 상태 유지·중복 이동·재처리 여부 기록 | |

화면별로 합의한 목적지·유지 상태·직접 진입 시 대체 동작·처리 담당과 검증 결과를 실제 카드에 연결합니다. API·Bridge 계약이나 이동 정책 중 필요한 근거가 남아 있으면 해당 연동 범위만 차단하고, 모든 카드에 딥링크·외부 복귀 검토를 요구하지 않습니다.
