앱·개발 화면·배포 경계 필수 기준

실제 앱, UI 검수 환경과 제품 배포 결과물의 책임 및 제외 기준

앱 초기 구성, 라우트 추가, 개발용 검수 화면, Storybook 설정, 빌드·배포 설정을 만들거나 바꾸기 전에 이 기준과 해당 앱의 실제 설정을 반드시 확인합니다. 같은 저장소에서 관리하더라도 제품 실행 코드와 개발·검수 결과물은 구분합니다.

1. 실행 목적과 배포 대상

구분목적제품 배포 포함
실제 앱사용자가 서비스에서 실행하는 화면과 기능실제 라우트·코드·런타임 자산 포함
StorybookComponent·Feature·Screen 전체 UI의 주요 상태 검수제외. 필요하면 별도 검수 환경으로 게시
개발용 preview개발 서버에서 화면 조합·이동·검수 흐름 확인라우트·소스·전용 스타일 제외
dist빌드 후 배포에 필요한 파일을 모은 결과물해당 앱이 명시한 배포 폴더만 전달

Storybook과 preview는 실제 앱에서 사용하는 UI를 가져와 확인합니다. 실제 앱은 Story, 개발용 화면, 검수용 Provider와 테스트 코드를 가져오지 않습니다. Story는 실제 구현 가까이에 두어도 되며, 폴더 위치만으로 배포 제외가 보장되지는 않습니다.

2. 구현 전에 정할 필수 항목

  • 이번 코드가 실제 앱, Storybook, 개발용 preview 중 어디에 속하는지 정합니다. 검수용 화면을 서비스의 기본 페이지나 운영 레이아웃에 연결하지 않습니다.
  • 실제 앱 라우트와 개발 전용 라우트의 구분 방법, 운영 빌드에서 개발 라우트를 제외하는 설정을 확인합니다.
  • 운영 코드의 import와 CSS 입력에서 개발용 소스·Story·테스트가 연결되지 않도록 합니다. TypeScript 제외 설정 하나만으로 번들 제외를 보장하지 않습니다.
  • 빌드 명령, 결과물 경로, 배포에 필요한 서버·정적 자산을 실제 설정으로 확인합니다. dist라는 이름만으로 정적 사이트 배포를 가정하지 않습니다.
  • 완료 기록에 변경한 경계와 확인 결과를 남깁니다. 검증을 생략한 경우 생략한 항목을 적고, 배포 경계가 검증됐다고 표시하지 않습니다.

3. WebView의 현재 적용 위치

범위현재 위치·처리
실제 앱front-end/webview/src/app/의 일반 page.tsx·layout.tsx·route.ts
공통 UI·기능src/components/·src/features/·src/lib/. 실제 앱이 사용하는 모듈 연결
개발용 previewsrc/dev/와 src/app/preview/. 개발 서버에서만 *.dev.tsx·*.dev.ts 라우트 인식
Storybook.storybook/와 구현 가까이의 *.stories.tsx
테스트src/test/와 *.test.*·*.spec.*. 제품 실행 코드에서 제외
제품 배포npm run build 후 dist/runtime/. Next.js 서버와 필요한 정적 자산 포함

WebView의 개발 화면은 npm run dev 실행 후 /preview에서 확인합니다. Storybook은 npm run storybook으로 실행합니다. 운영의 기본 페이지는 실제 서비스 진입점이며 검수 화면 목록으로 사용하지 않습니다.

구체적인 명령과 배포 방법은 WebView BUILD.md를 확인합니다. 실제 제외 설정은 Next 설정, 운영 TypeScript 설정, 런타임 패키징, 실행 명령에 있습니다. 경로·명령이 바뀌면 이 표와 앱 안내를 같은 변경에서 갱신합니다.

FO 웹·PO·OO에도 같은 분리 원칙을 적용합니다. 구체적인 라우트 방식과 결과물 경로는 해당 앱의 실제 설정이 정해질 때 기록하며 WebView 설정을 그대로 가정하지 않습니다.

4. 제품 빌드와 배포에서 제외할 내용

  • docs/·work/와 AGENTS.md·README.md·LINT.md·BUILD.md 등 개발 문서와 작업 지침.
  • .storybook/·Story 파일·Storybook 결과물, 개발용 preview 라우트·src/dev/·전용 스타일.
  • 테스트 소스·fixture·테스트 설정·coverage·테스트 보고서와 제품 실행에 필요하지 않은 개발 도구.
  • .git/·.github/ 등 저장소·자동화 설정과 로컬 환경 파일·캐시.

제외할 내용을 public/ 같은 정적 자산 폴더에 복사하지 않습니다. 앱에 필요한 공개 자산과 런타임 의존성은 포함합니다. 빌드 시 필요한 개발 도구와 배포 서버에서 필요한 런타임 파일을 구분합니다.

5. 변경 후 확인할 경계

  • 운영 라우트 목록에 preview·검수 화면이 없는지 확인합니다.
  • 운영 import, 타입 검사 입력과 CSS 입력에 개발 전용 코드가 섞이지 않는지 확인합니다.
  • 최종 배포 폴더에 문서·지침·Story·테스트·개발 전용 도구가 포함되지 않는지 확인합니다.
  • 개발 서버의 preview와 Storybook에서 필요한 UI를 계속 확인할 수 있는지 확인합니다.

설정 변경은 운영 빌드와 최종 결과물 확인이 필요합니다. 문서만 바꾸는 작업은 링크·문서 구조·검색 색인을 확인합니다. 실행하지 않은 검사는 완료 근거로 적지 않습니다.

6. 관련 기준과 변경 책임

저장소 구조·CI/CD 가이드, Front-End 개발 가이드, Storybook 요약, 품질 요약에서 이 기준을 함께 참조합니다. 앱별 BUILD.md는 실제 명령과 경로를 설명하고, 이 문서는 공용 필수 원칙을 관리합니다. 구현 방식이 바뀌면 실제 설정·앱 안내·이 문서의 해당 범위를 함께 수정합니다.
