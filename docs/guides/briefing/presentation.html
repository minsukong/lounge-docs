01 · BUILD STRATEGY

사람은 결정하고
AI는 기준 안에서 실행합니다.

가이드는 사람이 정한 방향을 AI가 실행 가능한 기준으로 바꾸고, AI의 결과를 다시 사람이 검토할 수 있게 연결합니다.

HUMAN · 방향과 판단

  • 제품 방향과 사용자 흐름
  • 업무 규칙과 우선순위
  • API·인증·Bridge 연동 방식
  • 보안·운영 정책
  • 변경 승인
  • 최종 품질 판단
가이드 체계 · 반복되는 판단을 공통 기준으로 유지
가이드로 연결⇢

AI · 탐색과 실행

  • 기존 Source 탐색
  • Component·Token 확인
  • 코드와 Story 초안
  • 상태·예외 누락 확인
  • 검사와 Build 실행
  • 변경 결과 정리
구축 결과 · Source, Story와 Test로 검토 가능하게 제공

GUIDE SIDEdocs/ 판단 기준, 배경, AI Context와 적용 조건을 제공합니다.

03 · DOCS LAYERS

같은 기준을
사용 목적에 맞는 깊이로 제공합니다.

docs/guides/사람용 상세 기준 원본
관계자와 실무자가 결정의 이유·배경·검토 방법까지 이해
핵심 결정만 작업별로 압축 ↓
docs/ai/AI Context Router
긴 문서 전체 대신 현재 작업에 필요한 제한과 판단만 제공
파일에 옮길 구체성이 필요할 때 ↓
docs/common-source/적용 조건과 파일 단위 구현 예시
정책 설명과 코드 예시를 분리하고 기존 Source와 비교·병합
실제 Package와 사용처를 확인해 선별 적용 ↓
apps/app-webview/실제 Source · Story · Test
문서 예시가 아니라 설치 상태와 기존 구현을 최종 사실로 사용
assets/ · 공통 스타일과 이미지
templates/ · 가이드 형식
search/ · 가이드 검색

04 · GUIDE MAP

가이드 하나는 구축의
하나의 결정 영역을 책임집니다.

백과사전식 분류가 아닙니다. 결정권자와 검증 시점이 다른 영역을 분리해 필요한 가이드만 선택할 수 있게 했습니다.

08 · AFTER BUILD

구축이 끝나면 가이드는
운영과 다음 변경의 출발점이 됩니다.

문서를 보존하는 것이 목적이 아닙니다. 다음 변경에서 다시 사용할 정확한 Context를 유지하는 것이 운영의 핵심입니다.
